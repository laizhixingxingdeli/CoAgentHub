# 控制台任务总览

只读总览。不新增分页协议或内核字段，不在 Web 上做审批、终审、暂停、取消或合入。

## 列表

六种主状态完整可见。暂停、补修、问题升级、direct 只作附标。需要你处理、进行中、最近结束按真实事实分组，组内按更新时间倒序。

五列是编号/intent、主状态/附标、处理人/下一步、费用、更新时间。未知费用不补零。direct 显示主控未计。统计取完整匹配集，不取当前可见批次。

## 补修附标

没有 repairOf 字段，也不把 rerun、重派或 executing/isMutating 当成补修。只认工单标题，或 `order.requiredBehaviour` 去掉首尾空白后的第一行开单声明。代码块、测试夹具、contextRefs、executionResult 和正文后部的讨论提到「补修」或 W-数字，不算声明。

L2 开补修单时使用约定声明，如「补修原项 W-888。缺口：……」「补修 W-888：……」或「本单补修原项 W-888……」，并写清剩余缺口；第一行写成「本单是补修，原项 W-888」不在当前支持句式内。普通实现单只在样例中讨论补修时，不将声明句式放在标题或正文第一行。

## 补充事实

首屏先出列表。只对可见任务读取既有详情和必要 Attempt，缓存且限并发。运行中只认真实 in_progress Attempt。集成落地只认 `finalReview.mergedInto`；没有 master 证据就显示未记录。

## 失败

初次加载、空项目、局部失败、服务离线与数据过期分开。刷新失败保留最后成功数据和选择。隐藏或离页取消旧请求。
