# 工程规范

用户 2026-10-02 定：以后经平台流程开发时都照这份规范（原话：「这些要当成以后用这个平台流程进行时的规范」）。数值是「坏味道预警线」，不是通过 / 不通过的红线——超线要在交卷或评审里说明为什么，或者拆。票里的数值目标同样写成建议值、不当硬性验收（用户同日：「只是建议1000行代码，没必要硬性要求」）。

## 一、代码

| 指标 | 预警线 | 为什么 |
|---|---|---|
| 函数长度 | 4–40 行 | 超过 40 行通常承担了多个职责 |
| 文件长度 | 4–400 行 | 超过 400 行通常难以被整体理解 |
| 圈复杂度 | 单个函数 < 15 | 超过 15 条独立路径，识别和测试成本显著上升 |
| 嵌套深度 | ≤ 3 层 | 超过 3 层需要反向追踪，认知负担明显增加 |
| 参数个数 | ≤ 4 个 | 超过后用对象或配置结构封装 |

共同逻辑：函数和文件应该在一个屏幕、一次思维聚焦内被理解。

可读性：

- 命名表达意图，不用缩写或单字母（`calculateSpeedKmh` 优于 `calc`）。
- 注释解释「为什么」，不解释「做什么」。
- 魔法数字提成具名常量。

## 二、架构（高内聚、低耦合）

- **单一职责**：一个函数、类或模块只有一个变化的原因。
- **显式依赖**：不依赖隐式的全局状态或系统级包，所有依赖在声明文件里列全（12-Factor）。
- **无环依赖**：模块依赖图里不许有环。
- **依赖方向单向**：高层依赖底层的抽象，不依赖具体实现。本仓已有的落地：内核（`src/kernel/`）不 import 任何东西。

## 三、协作（Git 与审查）

审查维度（参照 Google 工程实践，与语言无关）——协调者验收工作项、检视者看交卷时都按这五项：

1. **设计**：改动与系统整体结构协调吗？
2. **功能**：行为符合预期吗？边界情况处理了吗？
3. **复杂度**：是不是比必要的更复杂？（对照第一节的预警线）
4. **测试**：有设计良好的自动化测试吗？（同时守「测试尽量少」：只在关键地方、每条验收一到两条）
5. **命名与注释**：清楚表达意图吗？

流程：

- **小粒度变更**：一次只解决一个问题。平台里对应「一票一个 Mission、一张工单一个行为」。
- **至少一人审查**：提交者不能批准、合并自己的改动。平台里对应：执行者的改动由协调者验收；Mission 由检视者或机器 L3 合入集成分支；master 由用户签字。
- **提交信息规范**：用一致的格式，如 `feat:`、`fix:`、`docs:`、`refactor:`、`test:`、`chore:`。
- **主分支保护**：不直接改 main / master，所有改动经集成分支合入，master 由用户签字合入。
- **合并后删除分支**：Mission 分支合入后删掉。

## 四、自动化与 CI（靠工具链，不靠记性）

- 每次提交自动执行：格式化、lint、类型检查、单元测试。**本仓现状（用户 2026-10-02：「先不加」依赖）**：格式化、lint、类型检查暂不接入（要加开发依赖）；先用零依赖的度量与依赖环检查（STD1）作告警，单元测试照旧每次跑。
- 依赖锁定文件必须提交（本仓 `package-lock.json`）。
- 构建加测试的总时间控制在 10 分钟以内（本仓全量 `node --test` 约 2 分钟）。
- 密钥、证书、环境变量不进代码库。

## 五、文档（最低要求）

- **README**：项目是什么、怎么安装、运行、测试、部署。
- **API 文档**（对外暴露接口时）：端点、参数、请求 / 响应示例、可运行的示例。
- ADR、运维手册、CHANGELOG 按项目复杂度增加。本仓已有 ADR（`.coagent/architecture/decisions/`）与运行手册（`reviewer-runbook.md`）。

## 在平台流程里怎么用

- **检视者冻结票**：新代码的文件、函数守第一节的预警线；票里点名要改的大文件，顺带写明「不让它更大」。本仓 10-02 对照：十多个源文件超 1,000 行；`platform.ts` 已由 REF1 拆成入口外壳加 `src/application/platform/` 下 38 个模块（最大 754 行），其余大文件（`orchestrator.ts`、`api/server.ts`、`web/task.js` 等）以后按同样办法拆。
- **协调者**：拆工单时让单张工单的改动符合预警线；验收按第三节五个维度逐项看，超线的要么让执行者拆，要么在验收理由里写明为什么可以。
- **执行者**：命名、注释、常量照第一节；新函数不超过 40 行、嵌套不超过 3 层。
- **自动化**：度量检查、依赖环检查、格式与 lint、类型检查接进平台验证（VR1a），先作告警报告附在交卷里，不做硬拦。
