# Web 端不做前后端分离，也不引入构建

## 取舍

正式 Web 端（项目页 / 任务详情页 / 资源池页）写在同一个项目里，
前端拆成一组**无构建**的静态文件，由现有的 `node:http` 直接吐出去。

不采用：独立 Vite + React + Tailwind + Radix 项目（v4 的做法）。

## 为什么

1. **API 已经是完整的 versioned client API**（S12.1）。前端本来就是纯客户端，
   分不分离不改变耦合度，只改变部署形态——而多一个部署形态是净成本。
2. **零构建是这个项目的承载性质。** `node src/main.ts` 就能跑，
   这一条支撑了"随时起一个观测面看现场"。加构建步骤等于把它换成
   "先 install 再 build 再起两个进程"。
3. 浏览器原生 ES module 不需要打包。三个页面的复杂度在手写范围内，
   而这些页面要的是表格、tab、抽屉——不是 React 才能做的东西。
4. 真正的问题是**单文件会失控**（649 行涨到 2500 行），
   而那个问题的解法是拆文件，不是拆项目。

## 什么时候该推翻它

- 需要虚拟滚动、拖拽排序、富文本编辑这类自己写代价明显过高的组件；
- 页面数超过 ~8，手写路由和状态开始出错；
- 前端需要独立部署到 CDN / 独立扩容。

三条里出现任意一条，重开一个 ADR 推翻本条。在那之前
"换成 React 会更好写"不是理由——好写的是第一版，难的是第二年。
