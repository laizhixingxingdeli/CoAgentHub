# CoAgentHub 控制台 · 工程校样

operate

## Scope and Authority

本轮交付为任务总览、任务详情与模型资源管理及其变体的可编辑 Figma 桌面设计和导航原型。产品边界以 `PRODUCT.md` 为准，视觉规范以 `DESIGN.md` 为准；Web 仅查看进度及管理资源，审批、终审和合入留在主控会话。

Figma 文件：[CoAgentHub · 任务进度与模型资源](https://www.figma.com/design/fGZiQG7IlSFnXdqqkcCxX5)。任务总览为 2:47，三层详情为 2:140，直接主控详情为 41:488，资源为 2:214；备份页为 39:3。本轮数据和画板索引为 `.impeccable/review/p1-revision-manifest.json`，前轮索引保留于 `revision-manifest.json`。任务、候选、费用、119 条分页总数及报告项数均为合成材料，不是在线平台证据。

## Task Overview

主状态仅有调查中、规划中、执行中、等你检视、已完成、已中止六种；暂停、补修、问题升级和直接主控作为附标，不替代主状态。问题升级明确写“已升级（问题）”，Android 范围冲突样本有此标记，Vehicle 最终检视样本无此标记。八个样本包含调查中 1、规划中 0、执行中 4、等你检视 1、已完成 1、已中止 1。需要人工处理的 3 项分别由检视者处理 2 项、用户处理 1 项，均明确说明不会自动恢复；“执行中”但人工等待保持主状态文字并用琥珀色，只有真运行使用 running 蓝。自动退避另示处理人为平台、重试时刻与次数。

总览五列为编号/intent、主状态/附标、处理人/下一步、费用、更新时间，列宽为 400、194、290、144、100px。64px 高的记录分为需要你处理、进行中、最近结束；提供状态筛选、暂停筛选、编号/intent 搜索与加载更早入口，不静默截断统计。长编号中间省略，intent 一行摘要，完整编号与 intent 可查。一级导航仅为任务、资源，项目切换位于顶部信息条，本轮起点为全部项目。

## Mission Detail

页头层级为任务身份与当前状态 → 40px 任务事实信息带 → 页签 → 工作项与流程。任务事实用 nav 底色、细边界和 16px 内缩进，时间右对齐，不与流程步骤混作一组。

完整编号使用 Identifier，intent 默认两行，可展开完整内容。页头分别表达当前主状态、附标、处理人与下一步、执行保障、协作方式、费用及上限和质量；上限读取实际记录，不能为所有历史任务补成相同预算。外部会话的模型与费用明确标为平台不可见，未知不填零；直接主控不出现虚构的 L2 协调者。

详情有工作流、交付与验证、契约三个页签，对应画板为 1440×1240。当前实时输出与选中历史环节是两条独立查看轴：改变选中环节不会把历史输出冒充当前会话。输出功能区高 566px、内部终端高 444px；运行中显示最后输出与心跳，已结束会话显示最近输出和心跳不适用，疑似停滞有对应提示。

三层执行中、直接主控和待检视使用 W-684、W-712、W-1102 三组独立数据，创建时间、持续时长、日志、允许范围与验收不互相借用。每组历史有 15 个已发生环节，即 13 次执行加 2 个协调者或外部主控环节，按工作项、轮次与发生顺序展示；不把未来流程预铺为已发生。上游失败后的自动改派归因于平台调度器按候选顺序选择，不表述成协调者或外部主控切换候选。

默认收拢较早记录，展开后使用纵向 TimelineHistoryRow；支持选择历史记录、查看对应文件/用量、定位当前与收起历史。当前工单与其它已验收工单可切换。契约页保留修订及 intent、acceptance、constraints、nonGoals、guardrails、allowedScope 六个内容字段，acceptance 按条编号，不能用泛化说明取代任务自己的契约。

## Delivery and Evidence

机器验证、协调者或直接主控验收、适用时独立复核、检视者终审、集成分支合入、master 合入六层各自显示状态与证据。通过一层不代表后续已完成；不适用与未知保持独立。直接主控由外部主控验收，不冒充平台 L2。完成样本明确已合入集成而 master 未合入；中止保留已有证据，不等于交付验收通过。

执行中样本的失败报告 VR-1179 与尚未交卷的第 13 次执行分开，不能把历史失败或旧提交当作当前执行结果。直接主控样本尚未最终交卷，不显示捏造的最终 hash 或 diff；待检视样本才关联 VR-1182、受评提交 7c1e9a2 与交卷摘要。机器验证报告、受评提交与交卷摘要均须关联具体受评执行，以上编号均为合成示例。

## Model Resources

合成候选池共 12 条：协调者 8（其中停用 2）、执行者 4、独立复核 0、分类 0；这些数量是本轮样本，不是永久产品常量。尝试、成功、费用、额度和失败记录使用参差样本，保留未知与已上报为零的区别。列表显示顺序、候选/endpoint、启用、熔断、近七日尝试/成功/费用、额度/重置与占用；正常候选不凭空附加失败记录。48 字符 profileId 中间省略并悬停显示完整值，未知健康、费用未上报、额度不可读与空角色都有明确表达。

每个角色只有一份草稿与一条保存栏；添加/编辑候选、启停、排序及参数变更都进入本角色草稿，由同一保存入口携带 revision 提交整角色配置。空角色不显示保存栏，不在候选抽屉里形成第二套保存边界。profileId 只读，runtime=pi，facts 使用参数键值输入框；endpoint（包括 local 项）来自合成目录，不代表当前在线模型清单。首位上移禁用，保存与取消有状态导航。配置冲突禁用保存，重新载入只由冲突入口触发；保存只影响之后派发，不宣称打断运行中的执行。

健康详情只读，复位命令保留平台给出的原文形状 `node src/l3.ts candidate reset <profileId> --reason "…"`，来源为 `src/api/server.ts`，仅显示，不执行。额度按窗口自动重置与需充值的耗尽分别说明；充值完成后仍需按实际恢复条件人工复位，不能将充值写成自动解除熔断。平台未给命令时显示原因并禁用复制；原型的“已复制”仅展示状态，不操作真实剪贴板。

## Data States and Locations

| 场景 | 明确出现位置与处理 |
| --- | --- |
| 服务未运行 | 顶栏下方页面级横幅，保留最后数据时刻，显示已核实的本机启动命令 |
| 数据过期 | 顶栏同步状态位，显示最后同步时刻与过期提示 |
| 首次加载 | 列表内部骨架，不伪装成可点击按钮 |
| 空项目/空角色 | 相应内容区解释无记录，任务创建仍由检视者会话完成 |
| 局部失败 | 仅失败单元格显示错误，其余已知数据继续可见 |
| 未知值 | 原字段位置明确显示未知、未上报或平台不可见，不补零 |
| 可能停滞 | 当前输出区显示最后输出、心跳及检查会话提示 |
| 接近或达到预算 | 费用区显示实际费用/上限；停止门禁说明处理人 |
| 保存失败/修订冲突 | 编辑区域显示错误；冲突禁用保存并提供重新载入 |

## Prototype, Fonts and Verification

原型只有“任务查看与资源草稿管理”一个起点，不将各变体画板另设为孤立流程；重新载入从配置冲突触发。输入、保存、复制和重载均为 Figma 状态导航，不是接口、运行时或剪贴板实现。`.impeccable/review/p1-structural-audit.json` 记录本轮 973 条带目标动作、0 个失效目标、0 个低于 13px 的文本、0 个未绑定样式文本及 0 个旧候选占位；重新载入有 1 个入口，17 个非空资源场景各 1 个保存入口，2 个空角色场景均无保存入口。这些数值仅为本轮设计检查快照。逐项结果见 `p1-spec-checklist.md`，最新 14 张渲染截图为 `p1-*.png`，数据与画板对应关系见 `p1-revision-manifest.json`；独立复核 ship 仅限本轮 P1/P2 桌面修订。

固定页名字体子集与回退说明见 `.impeccable/assets/fonts/README.md`。6436 字节 WOFF2 已生成；`measure_fallback.py` 与 `font-width-check.json` 记录本机微软雅黑、Consolas 对任务字段、12 条候选的列表省略编号、抽屉完整编号与历史完整角色编号共 92 项字宽实测，均适合给定宽度。Figma 不提供这两字体，因此不能把字宽测试写成画板已真实回退渲染；字体子集尚未接入生产静态服务。

## Remaining Boundary

界面移除“L3 检视者：外部会话 · 模型与费用平台不可见”“合成数据 · 非实时”“≈ 为估算；主控未计不等于零”等重复介绍；设计示例边界保留在文档中。字段自身仍显示未知、估算或主控未计，错误及恢复指引保留。任务事实带改为 40px 单行，并收紧删除说明后的空位。

针对“各部分区分不够明显”的修订，导航采用深墨色，详情任务页头采用白色信息层；总览和候选列表采用完整白底区域，分组标题、列头及功能区标题带采用 nav 底色。已查看三张主页面导出，底板完整覆盖末尾记录，任务和候选行仍保持 64px。文字与状态语义沿用已批准版本，证据为 `.impeccable/review/sections-*.png`。

本轮 polish 保留全部已核准语义与示例：统一顶栏同步信息的右侧锚点、保存条按钮的右侧锚点、分组标题的行内缩进；时间线身份文字预留 40px 两行，结果行共用基线。待确认文件行数使用中性辅助色。已查看总览、详情、资源及熔断抽屉的实际导出，结构检查见 `.impeccable/review/polish-audit.json`；这些检查不替代生产端的键盘、读屏或响应式验收。

生产 `src/`、真实接口和候选池未修改。移动端、其它桌面尺寸、全浏览器字体回退与运行时操作仍待后续实施和验收；不将桌面设计检查扩大为生产接受结论。
