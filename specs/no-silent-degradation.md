# Spec: 静默降级要有可见信号

> **状态**: Landed — L1/L2/L3 均通过(2026-08-23)
> **版本**: 1.0
> **日期**: 2026-08-23

## 背景:这是系统性模式,不是零星 bug

一轮实测里撞到的静默降级:

| 现象 | 后果 | 状态 |
|---|---|---|
| `POST /groups` 丢弃 `projectPath` | 三个群都没绑上项目 | 已修 `f83e06a` |
| 建群者角色写死 coordinator | 模式静默退化两层,L3 整层消失 | 已修 `f83e06a` |
| 加群无条件发 skill 引导 | 五个群五条重复 | 已修 `0a8c160` |
| ANSI 未剥离 | 前端乱码 | 已修 `b30a4a9` |
| **MCP `callbackRef` 为 null** | 执行器完成不回调协调者,协调者傻等 | **未修** |
| **下发不强制 `specHash`** | 验收钉子形同虚设 | **未修** |

**共同点:平台一律选择「安静地继续」而不是「报错」。**
对一个以可观测性为卖点的系统,这个默认值是反的。

前四条已各自修掉,但都是**逐个打补丁**。本票处理剩下两条,
并把原则写进文档,免得下次又漂回去。

---

## 要求

### R1. 下发时缺 `specHash` 要有信号

`task` 表的 `spec_ref` / `spec_hash` 均可空(`schema/task.ts:90-91`),
下发路径也不强制。而 spec v3.8 明确要求 `specRef` + `specHash` 是**验收钉子**——
缺了它,L2 无从对照。

- **群内存在 `reviewer` 角色成员时**(即走 spec 驱动流程的群),
  下发缺 `specHash` 的任务应产生**可见信号**
- ⚠️ **不要直接拒绝下发**:群里可能有正当的指令驱动任务(运维、探测),
  一刀切会打断既有用法。信号形态自行设计(响应字段警告 / 群内提示 /
  任务上标记皆可),**在汇报里说明选了哪种及理由**
- 无 reviewer 成员的群不产生信号(那本就不是 spec 驱动流程)

### R2. `callbackRef` 被剥离时要有信号

`routes/group/messages.ts` 的 callback 处理:发送者无权携带 dispatcher 信息时,
**整个 callback 被静默丢弃**(`canCarryDispatcher` 为假 → `callbackRef` 保持 null)。

实测后果:协调者下发给执行器的任务 `dispatcherSessionId` 与 `callbackRef` 全是 null,
执行器完成时**不会回调协调者**——协调者只能主动轮询,而它并不知道自己需要轮询。

- 调用方**明确传了 `callback` 但被剥离**时,要有可见信号告知
  (与「压根没传」区分开——没传是正常的,传了被吞才是问题)
- 信号形态自行设计并说明

### R3. 把原则写进文档

在 `docs/architecture.md` 增补一节(或并入既有的约定章节),写明:

> **凡是「调用方本意要生效、实际没生效」的路径,必须有可见信号**——
> 报错、响应里的警告字段、或群内消息,不能什么都不说。
>
> 静默丢弃未声明字段(zod 默认行为)、静默回落默认值、静默跳过某项处理,
> 在本项目里都属于需要显式处理的情况,不是可接受的默认。

并把上表(已修四条 + 本票两条)作为实例附上,让后来者知道这不是空泛原则。

## 验收标准

- [ ] 有 reviewer 成员的群里,缺 `specHash` 的下发产生可见信号
- [ ] 无 reviewer 成员的群不产生该信号
- [ ] **不因缺 specHash 拒绝下发**(指令驱动任务仍可用)
- [ ] 明确传了 `callback` 却被剥离时有可见信号
- [ ] 没传 `callback` 时**不**产生信号
- [ ] `docs/architecture.md` 有该原则,含实例表
- [ ] 两处信号的形态选择已在汇报中说明
- [ ] 新增测试覆盖:有/无 reviewer 群的 specHash 信号、callback 被剥离与未传两种情况
- [ ] `pnpm --filter server test` 全绿(先跑一次确认基线,不得减少)

## 不涉及

- **不改**前端
- **不回头改**已修的那四条(它们各自的票已落地并通过 L3)
- **不改**全信模型下 `canCarryDispatcher` 的判定规则本身——本票只要求
  「被剥离时说一声」,不改谁有权携带
- **不做**全局的「静默降级审计」——本票只处理已确认的两处 + 立原则
- 不引入新依赖
