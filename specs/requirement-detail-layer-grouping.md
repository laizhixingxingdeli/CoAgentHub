# Spec: 详情页按「层」组织,不再按时间堆

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-24
> **前置**: `layer-status-contradiction`(`97dcf397`)、
>   `structured-payload-rendering`(`b7c2cf1f`)—— 先修正错误,再重排布局

## 现象

详情页现在是「阶梯 + 三张层卡片 + 一条混合时间线」。时间线里并排着三种性质
完全不同的东西:

- 执行任务卡片(带回滚按钮、耗时、失败条)
- 检视者公布的裁决载荷
- 协调者的汇报

没有分隔、没有分组,**只按时间堆**。而信息在层卡片与时间线里**各出现一次** ——
读者要在两处之间来回对照才能拼出「这条需求到底发生了什么」。

折叠入口也占了整行,而折叠态**只显示字数**,没有任何内容线索:

```
∨ 展开 · 454 字
```

上一轮要求「入口要显眼」,结果矫枉过正:**入口比它要展开的内容还占地方**。

## 决策:三段式,每层自带其产物

```
L3 检视   状态徽章 · 裁决摘要                        [展开]
L2 协调   状态徽章 · L2 结论                          [展开]
L1 执行   状态徽章 · N 次执行                         [展开]
          └ 执行记录(任务卡片、输出、控制)
```

**时间线不消失,而是归位** —— 每条记录落到它所属的那一层里。

### R1. 三段式布局

按 **L3 → L2 → L1** 自上而下(与阶梯方向一致,结论在前、过程在后)。

- 每段是可折叠区块,**标题行内含**:层名 + 状态徽章 + 一行摘要 + 折叠控件
- **折叠控件收进标题行右侧**,不独占一行(解决「入口比内容还占地方」)
- 层内无内容时,标题行仍在(显示状态),**不隐藏该层** ——
  「这层没发生」本身是信息

### R2. 每条记录归入其所属层

| 记录 | 归属 |
|---|---|
| 执行任务卡片、执行输出、停止/回滚控制 | **L1** |
| 协调者的 L2 结论、`review_request` 事件 | **L2** |
| 检视者的 `review_result` 事件、`spec_amended` | **L3** |
| 任务书、群内对话等自由文本 | **L1**(执行与沟通记录,沿用现名) |

无法判定归属的记录 → 放 L1 段末尾,**不丢弃**。

### R3. 折叠态要有内容线索,不只有字数

折叠时显示**首行摘要**(截断)而非仅「454 字」。字数可保留为次要信息。

理由:字数不能帮人决定要不要展开;首行可以。

### R4. 默认展开策略

- **有发现项 / 失败 / 未检视** 的层 → **默认展开**
- 全部正常通过 → **默认折叠**

理由:需要注意的东西应当直接可见,顺利的部分不占视线。

### R5. 保留既有能力,不得丢失

- 停止/回滚控制仍在任务卡片上(`requirement-detail-control-placement` 已落地)
- 现有 `data-testid` **沿用**,不改名
- 长内容的高度上限与内部滚动(`fold-affordance-and-length-cap`)**保留**

### R6. 不改这些

- **不改**后端
- **不改**阶梯本身的语义(`requirement-stepper-semantics` 已定:固定三步、单位是层)
- **不改**载荷解析(前置票已处理)

## 验收标准

- [ ] 详情页按 L3 / L2 / L1 三段组织,顺序自上而下
- [ ] 折叠控件在**标题行内**,不独占整行
- [ ] 折叠态显示**首行摘要**,不是只有字数
- [ ] 有发现项 / 失败 / 未检视的层**默认展开**;全部通过时默认折叠
- [ ] 执行任务卡片、输出、控制按钮全部归入 **L1 段**
- [ ] `review_result` / `review_request` 事件条目归入对应层
- [ ] 层内无内容时**标题行仍显示**(不隐藏该层)
- [ ] 停止/回滚**仍可用**,`data-testid` 未改名(回归,必测)
- [ ] 长内容仍有高度上限与内部滚动(回归,必测)
- [ ] 同一份信息**不在两处铺全文**
- [ ] 前端测试全绿,贴出用例数
- [ ] **未改动**后端

## 不涉及

- 阶梯语义(已定)
- 载荷解析(前置票)
- 左栏列表(另票 `requirement-list-title-prefix`)
