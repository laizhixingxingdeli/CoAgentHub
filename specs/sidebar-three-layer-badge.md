# Spec: 侧栏用「检视者」徽章表示三方编制,读起来像身份标识

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-23

## 背景

侧栏会话列表在群名旁挂了一个徽章
(`components/sidebar/conversations.tsx:142-147`):

```tsx
{group.memberRoles?.includes("reviewer") &&
  group.memberRoles.includes("coordinator") && (
    <span className="shrink-0" title="三层协作">
      <RoleBadge role="reviewer" />
    </span>
  )}
```

**判定逻辑是对的**(两个角色同时在场,符合 v3.9 §3.14.5),错的是**符号选择**:
它用「检视者」这个**角色**徽章去表示「三方编制」这个**编制状态**。

用户看到群名旁边一个「检视者」标,第一反应是「我在这个群里是检视者」——
而这条信息既不正确(徽章与本机身份无关),也不是这里想说的。

**同一件事在群组列表页做对了**(`pages/app/groups/index.tsx:365-366`):
两个角色徽章都显示,外加一个 `两层协作` 的文字兜底。**侧栏只抄了一半**。

## 要求

### R1. 不要用角色徽章表示编制

编制是「这个群配了几方」,不是「谁是什么角色」。用一个**编制专属的符号**:
文字标签(`三方` / `三层`)、中性图标、或计数形态皆可。

**不得**复用 `RoleBadge`。

### R2. 判据保持 v3.9 口径

**reviewer 与 coordinator 同时在场**才算三方。现有判定正确,**不要动它**。

⚠️ 别「顺手」改成只判 reviewer —— 那是 v3.8 的旧判据,已被 §3.14.5 推翻。

### R3. 与群组列表页表达一致

同一件事在两个地方不能有两套说法。

- 若群组列表页的表达合理 → 侧栏对齐它
- 若两处都该改 → **一并改**,并在汇报中说明

侧栏空间窄,可以更紧凑,但**语义必须同一**:不能一处叫「三层协作」、
另一处叫别的。

### R4. 两方编制不留空白

现在两方编制时侧栏**什么都不显示**,群组列表页显示 `两层协作`。

**要求侧栏也表达两方状态**(哪怕只是一个更淡的标),否则用户无法区分
「这是两方群」与「这个群的编制信息还没加载出来」。

⚠️ **中性色,非警告色** —— 只部署两方是合法且常见的选择(spec v4.0 §3.14.6)。

### R5. 术语跟随 v4.0

spec v4.0 起,「三层 / 两层」指**检视深度**(由工作类型决定),
「三方 / 两方」指**编制**(由成员构成决定)。这个徽章表达的是**编制**。

沿用旧词「三层协作」会与 v4.0 的术语冲突。**建议改用「三方 / 两方」**;
若执行者认为旧词对用户更易懂,可保留,但要在汇报里说明理由。

## 验收标准

- [ ] 侧栏徽章**不再是** `RoleBadge`
- [ ] 三方编制的群显示编制标识,两方编制的群也有(更淡的)标识
- [ ] 两方标识用中性色,非警告/危险色
- [ ] 判据仍是 reviewer 与 coordinator **同时在场**
- [ ] 侧栏与群组列表页的表述**语义一致**
- [ ] `title` / `aria-label` 说明该标含义,悬停可读
- [ ] 群名很长时徽章不被挤掉、不撑破布局(实测一个长名群)
- [ ] 前端测试全绿,贴出用例数
- [ ] **未改动**后端

## 不涉及

- 群组列表页的其它徽章与布局(除非按 R3 一并对齐)
- `RoleBadge` 组件本身
- 编制判定逻辑

## 执行环境提示

- 前端 `http://localhost:5173`
- 现有三个群均为三方编制。**两方场景需自建一个只有 coordinator + executor 的群验证**
