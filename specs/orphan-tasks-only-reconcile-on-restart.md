# Spec: 孤儿任务只在重启时收敛,与自动重建互为死锁

> **状态**: Landed — L3 通过(2026-08-27),实现 `3cd3435e`
> **版本**: 1.0
> **日期**: 2026-08-27

## 现象

执行器进程已退出,任务状态仍挂 `running`,形成孤儿。目前**只有后端重启**
才会把它们收敛为 `failed`;运行期间没有任何机制主动收敛。

实测:任务 `01a03ec7` 的 pid 56282 早已退出,状态仍为 `running`,
持续 29 分钟无人处理,直到我手工重启后端才被收敛。

## ⚠️ 危害:与自动重建互为死锁

`rebuild-when-runtime-goes-stale` R4 规定「有 running/queued 任务则跳过重建」。
孤儿任务同样命中该判据,于是:

```
要清孤儿  →  得重启后端
要重启    →  R4 要求先没有在途任务
孤儿挂着 running  →  R4 永远跳过
```

实测看门狗连续三轮(00:18:33 / 00:20:01 / 00:23:33)记录
「存在 running/queued 任务,本轮跳过重建」,全部由该孤儿造成。
**孤儿不清 → 自动重建永不执行;而孤儿只在重启时才清。**

## 现状盘点(已具备,不要重写)

- `lib/detached-task-liveness.ts` —— 已有 `DETACHED_LIVENESS_THRESHOLD_MS`
  (30 分钟)与 `computeLastSignalMs`,判据是**输出时间戳**
- `lib/executor-task-liveness.ts` —— 执行器任务的同类判定
- 两者目前**只在 `routes/group/tasks.ts:722` 的 GET 路径被调用**,
  产出 `livenessWarning` 布尔供前端展示,**从不写回 `task.status`**
- 全库仅两处 `setInterval`(`ws-hub.ts:445` 心跳、
  `coordinator-resume.ts:265`),均不负责任务状态收敛

即:判定逻辑齐全,缺的是**驱动**与**写回**。

## 要做的

### R1 — 增加周期性孤儿收敛

在服务端增加一个周期任务,扫描 `running` 状态的任务并收敛确已死亡的。
⚠️ **必须复用** `detached-task-liveness` / `executor-task-liveness` 的现有判定,
不得另写一套活性口径。

### R2 — 判据必须以进程存活为准,不能只看输出时间戳

现有阈值是「30 分钟无输出」。⚠️ 该口径**不足以判定孤儿**:
长时间思考或长命令执行都可能超过 30 分钟而进程完全健康,误杀正在干活的任务
比孤儿本身更糟。

收敛条件必须同时满足:
- 任务记录有 `executorPid`
- 该 pid **确已不存在**(如 `process.kill(pid, 0)` 抛 ESRCH)

⚠️ pid 存在但长时间无输出 → **不收敛**,维持现状(可保留 `livenessWarning` 提示)。

### R3 — ⚠️ pid 复用风险

pid 会被操作系统回收复用。仅凭「pid 存在」不足以证明是**同一个**进程。
实现需说明如何降低误判(例如结合任务的 `attempts[0].startedAt` 与进程启动时间比对),
或明确记录该风险与所选取舍。

### R4 — 收敛必须留痕

收敛写入的终态需在 `diffSummary` 中写明原因(如
`reconciledReason: "executor pid <n> no longer exists"`)与收敛时刻,
让事后能区分「执行器自己报的失败」与「平台收敛的孤儿」。

### R5 — ⚠️ 不得与正在写回的任务抢状态

执行器可能正在回写终态。收敛需以任务当前状态为条件更新
(仅当仍为 `running` 时才写),避免覆盖执行器刚写入的 `done`。

### R6 — 暴露 pid 存活信号

任务详情/列表 API 增加可靠的存活信号(如 `executorPid` 与 `pidAlive`),
供看门狗等外部消费方判断,不必各自猜测。
⚠️ 这是 `rebuild-when-runtime-goes-stale` 的协调者明确要求的前置条件
(其 R6 禁止在该票内改动平台 API,故拆到本票)。

### R7 — ⚠️ 范围限制

不改结案守卫,不改 `runtime-status.ts`,不改看门狗脚本。
看门狗侧如何消费 R6 的新信号,是后续独立议题。

## 验收要点

- 构造孤儿(启动任务后直接 kill 执行器进程),验证周期任务在一个周期内
  将其收敛为终态,且 `diffSummary` 含收敛原因(贴出记录)
- pid 仍存活但超过 30 分钟无输出的任务 → **不被收敛**(必测,防误杀)
- 执行器正在回写 `done` 时不被收敛覆盖(R5,并发用例)
- 任务详情 API 返回 `executorPid` 与 `pidAlive`(R6,贴响应片段)
- 汇报中说明 pid 复用风险的处理方式或取舍(R3)
- 测试全绿,贴出用例数
