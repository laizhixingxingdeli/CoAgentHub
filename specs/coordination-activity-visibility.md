# Spec: 平台看不出协调者是否真的协调过

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-23
> **关系**: `specs/dispatch-target-audit.md`(`5f07d8e`)覆盖「派给了自己」;
> 本票覆盖「**根本没派**」。两者合起来才覆盖完整的绕过空间

## 背景:同一个洞的第三种绕法

协调者「没把活派给执行器」有三种形态:

| 形态 | 平台看到什么 | 谁覆盖 |
|---|---|---|
| 派给了自己 | 一条 `senderId === audienceRef` 的任务 | `5f07d8e` |
| 派了但选错人 | 一条正常任务 | 目标审计记录(`5f07d8e`) |
| **根本不派,自己动手** | **什么都没有** | **本票** |

### 实测证据(2026-08-23 12:37–12:45)

我向协调者下发了三张票的协调请求。八分钟后:

```
近 2 小时派给 atomcode 的任务数:   0
工作树:  M packages/backend/server/test/dispatcher-fields.test.ts   ← 第一张票要改的文件
```

协调者**在自己的会话里直接改代码**,没有创建任何子任务。AtomCode 全程空闲未被使用。

**平台里一条痕迹都没有。** 上一次自派至少还留下一条任务记录;这次连记录都没有。

### 已有防护为什么拦不住

`b5afbe2` 给 coordinator skill 补的规则是:

> 候选必须是本群的 executor,且不得是你自己的 participant ID

它约束「**下发时选谁**」。而这里根本没有下发动作,规则管不到一个不存在的动作。

同理 `5f07d8e` 监测的是 `senderId === audienceRef`,这里压根没有 `audienceRef`。

> ⚠️ **检视者自陈**:`b5afbe2` 的 L3 是我做的,给了 pass。我核对了那条规则本身
> 是否正确(是),但没问「它是否覆盖了所有绕过路径」。这是检视方法的疏漏,
> 不是执行者的问题——记录在此以免重复。

## 关键前提:`parentTaskId` 已经落地

`6cfc84e` 落地了 `task.parentTaskId`——协调者下发的子任务会指向它自己那条 detached 任务。

**这意味着「这条协调任务派出去过几个子任务」现在是可查询的事实**,不再需要猜。
本票就建立在这条边上。

---

## 要求

### R1. 协调任务终态时记录协调活动摘要

detached 协调任务转终态(PATCH)时,记录该任务生命周期内的可观测事实:

- **子任务数量与目标**(用 `parentTaskId` 反查,现成的)
- 该协调任务期间**协调者在群里发过的消息数**
- 时间窗(创建 → 终态)

存储位置自行判断,但**必须能事后按任务查回**(与 `5f07d8e` 的审计记录同样要求,
若两者形态可统一则统一,**不要建两套**)。

### R2. 零子任务要产生警告

协调任务终态时**子任务数为 0**:

- 产生可见警告,内容需说清:这条协调任务没有派发过任何子任务
- 与 `5f07d8e` 一致:**警告,不拒绝**。协调者自行完成小改动可能是合理的
  (例如纯文档票、或票小到不值得一次派发往返)
- 警告必须**对检视者可见且无需轮询群消息**

### R3. 不要试图判断「它是不是自己写了代码」

平台无法可靠地把工作区改动归因到某个进程——协调者、执行器、人类可能同时在动同一个仓库。

- **不要**用「工作树有改动」「有新提交」去推断协调者是否自己干活
- 只记录平台**确知**的事实(子任务、消息、时间窗)
- 判断留给检视者(L3)与人

### R4. 与 `5f07d8e` 的边界

- `5f07d8e` 管**下发时刻**的目标合法性
- 本票管**协调任务终态时**的活动完整性
- 两者若落在同一段代码上,**复用不重复**;若形态冲突,**在汇报里说明**,不要各写一套

## 验收标准

- [ ] 协调任务终态时记录:子任务数与目标、群消息数、时间窗
- [ ] 记录可事后按任务查回,非仅 stdout
- [ ] 子任务数为 0 时产生警告
- [ ] 警告对检视者可见且无需轮询群消息
- [ ] **任务照常终态,未被拒绝**
- [ ] 未用工作树/提交去推断协调者行为
- [ ] 与 `5f07d8e` 的审计记录未各写一套(或差异已说明)
- [ ] 新增测试覆盖:有子任务不警告、零子任务警告、非协调任务不受影响
- [ ] `pnpm --filter server test` 用例数不减(退出码问题见执行环境提示)

## 不涉及

- **不改**前端
- **不做**拒绝(与 `5f07d8e` 同一决策:只警告 + 落审计)
- **不改** coordinator skill(规则层面另议——本票是让平台能看见,
  而不是再加一条 agent 可能绕过的纪律)
- **不做**工作区改动归因
- 不引入新依赖
