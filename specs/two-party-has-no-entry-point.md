# Spec: 「协调者 + 执行者」两方编制没有任何触发入口

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-25
> **发现于**: 试图端到端验证 `coordination-close-integrity` R2 的两方分支时

## 背景:R2 的两方分支无法被验证

`coordination-close-integrity` R2 规定:

```
应走 L3  ⟺  群内 reviewer 与 coordinator 同时在场  AND  dispatchKind != 'fix'
```

两方编制下不应要求 `review_request`。**这条分支只有单元测试,从未端到端跑过。**

尝试验证时发现:**两种两方编制各自卡在不同地方,都跑不通。**

### ① 「协调者 + 执行者」:无人能发起

按 spec §3.14.5,该组合适用于「无人值守 / 外部系统触发」。实际构造后:

- 群成员:`human` + `coordinator` + `executor`
- 以 human 身份发消息 → **403**「群是 agent 协作空间,请与检视者 agent 直接对话」
  (`routes/group/helpers.ts:75`,spec §3.8 的 human 只读守卫)
- 用 `audience: "role"` 角色定向**也绕不过** —— 守卫在消息层,先于派发层

**群里除了 human 没有第三方能发起,而 human 被禁言。** spec 说它适用于
「外部系统触发」,但**平台没有提供那个外部触发入口**。

### ② 「检视者 + 执行者」:群里根本没有协调任务

- 检视者能发消息(200),链路能跑
- 但群内**无 coordinator 成员**,检视者直接下发给执行器
- 于是**不存在协调任务**,而 R2 的强制只作用于协调任务
  (`isDetachedTask()` 为假直接跳过)

**测不到「两方编制下结案不要 `review_request`」这件事。**

## 决策:给两方编制一个合法的触发入口

### R1. human 可以下发任务,但仍不能自由发言

放宽 `human` 只读守卫的**范围**,而非取消它:

| 行为 | 现状 | 改后 |
|---|---|---|
| 自由文本发言 | 403 | **仍 403**(§3.8 不变) |
| 携带 `specRef` + `specHash` 的任务下发 | 403 | **放行** |

判据:消息**同时**带 `specRef` 与 `specHash`(即规范驱动下发),
且 `audience` 为 `role` 或 `participant`(定向下发)。

**理由**:§3.8 的立论是「群是 agent 协作空间,人应与检视者对话而非直接插话」——
这挡的是**闲聊**。而**下发一张有冻结 spec 的任务**不是插话,是外部触发,
正是 §3.14.5 所说「无人值守 / 外部系统触发」的那个入口。

⚠️ **不要整体取消 human 守卫。** 无 specRef 的自由文本仍应 403 ——
否则 §3.8 形同虚设。

### R2. 放行的下发要留痕

human 触发的任务,`dispatchAudit` 中标明触发方是 human。

理由:两方编制下没有检视者做 L3,**触发来源是唯一能追溯责任的线索**。

### R3. 不改 R2 强制本身

`coordination-close-integrity` 的判据**完全不动**。本票只解决「两方编制没有
入口所以那条分支跑不起来」,不改变它跑起来之后的行为。

### R4. 不改「检视者 + 执行者」编制

那种组合本来就能跑,只是不产生协调任务 —— 这是**设计如此**(检视者兼任下发,
没有中间层),不是缺陷。**不要为了让它产生协调任务而做任何改动。**

## 验收标准

- [ ] human 成员发**带 `specRef` + `specHash` 的定向消息** → **200**,任务被创建
- [ ] human 成员发**自由文本**(无 specRef)→ **仍 403**,错误信息不变(回归,必测)
- [ ] human 发带 specRef 但 `audience: "broadcast"` → **仍 403**
      (定向才算下发,广播仍是发言)
- [ ] 只带 `specRef` 不带 `specHash`(或反之)→ **仍 403**
- [ ] 放行创建的任务,`dispatchAudit` 可看出触发方是 human
- [ ] 非 human 角色的行为**完全不变**(回归,必测)
- [ ] **未改动** `coordination-close-integrity` 的判据(R3)
- [ ] 后端测试全绿,贴出用例数

## 不涉及

- 取消 human 只读守卫(R1 明确只放宽范围)
- 「检视者 + 执行者」编制(R4)
- R2 强制逻辑本身(R3)
