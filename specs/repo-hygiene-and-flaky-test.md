# Spec: `.pnpm-store` 未忽略 + 后端测试存在真实抖动

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-24

## 背景:两件仓库卫生问题,第二件此前被我误判过

### ① `.pnpm-store` 从未被 gitignore

它整轮都出现在 `git status` 里。并发撞车清理时**它一度被 `git add -A` 卷进暂存区**
—— 差点把整个 pnpm 包缓存(数万个文件)一起提交,靠 `git reset` 才拦下。

这不是洁癖:**一个不该被追踪的大目录长期出现在 `git status` 里,会让人对
「工作树是否干净」这个判断脱敏**,而本轮多次决策(能不能重启、要不要清理)
正是基于这个判断。

### ② 后端测试有真实抖动,概率约 1/3~1/7

`Failed Tests 1` 在本轮出现过多次,我每次都归因为「并发访问同一个 postgres
测试库」然后跳过。

**这个归因是错的。** 查证后确认:`test/setup.ts` 用 `vi.mock` 把
`@server/lib/database` 换成了**内存 PGlite**,每个测试文件独立,
**根本不连真实 postgres**。

实测复现:连跑 3 次 → 第 3 次 `1 failed | 553 passed`;再连跑 4 次 → 全绿。
**是真实存在的不稳定,不是「瞬时噪音」。**

### 为什么这件事重要

**「测试全绿」是每一次 L2 与 L3 的主要证据。** 证据本身以 1/3 概率翻转,
所有基于它的结论都要打折。而我反复用「瞬时噪音」把它挡回去 —— 那是在
**用一个未经查证的解释,维护一个我想要的结论**。

## 要求

### R1. 忽略 `.pnpm-store`

`.gitignore` 增加该目录。**同时确认它当前未被追踪**(若已被追踪需
`git rm -r --cached`,但据观察它一直是 untracked,应当只需加一行)。

### R2. 定位抖动的真实原因

**先查证,再修**。不要照搬我上面的任何猜测 —— 我此前的归因已经错过一次。

已知事实(可直接引用,无需重新验证):

- 测试用内存 PGlite(`test/setup.ts` 的 `vi.mock`),**不连外部 postgres**
- vitest 未配置 `poolOptions`,默认按 CPU 核数并行测试**文件**(本机 10 核)
- 45 个测试文件、554 个用例
- 失败时只报 `1 failed`,**失败用例的身份未被捕获** —— 这本身是排障障碍

排查建议(非结论):可疑方向包括跨文件共享的模块级单例(如
`executor-task/state.ts` 里的 `executorCooldowns` / `groupQueues` 等内存态)、
定时器未清理、以及依赖真实时间的断言。

### R3. 让失败可复现、可定位

无论根因为何,**必须先让失败暴露出身份**:

- 配置 vitest 在失败时输出**完整的失败用例名与断言差异**
  (当前输出只有 `1 failed`,无法定位)
- 若根因是并行导致的相互污染,记录**是哪两个文件**冲突

**这一条即使根因暂时无法根除也必须完成** —— 一个无法定位的失败,
比一个已知的失败更危险。

### R4. 修复或隔离

按 R2 的查证结果:

- 能根除 → 根除
- 短期无法根除 → **隔离**(例如给冲突文件加 `describe.sequential`,
  或对特定文件禁用并行),并在代码注释里写明**为什么**,附上复现方式

⚠️ **不要用「重试直到通过」的方式掩盖** —— 那会把不稳定变成永久的沉默。

### R5. 不改测试断言来「修」抖动

若发现某条断言依赖时序或共享状态,**改的是被测代码或测试隔离方式,不是把断言
放宽**。放宽断言等于删掉一次检查。

## 验收标准

- [ ] `.gitignore` 含 `.pnpm-store`,`git status` 不再显示它
- [ ] 确认该目录未被 git 追踪
- [ ] 后端测试失败时,输出**包含失败用例的完整名称与断言差异**
- [ ] 查证结论写进汇报:根因是什么、依据是什么
- [ ] **连续运行后端测试 10 次全部通过**(这是本票的核心验收 ——
      少于 10 次不足以证明抖动已消除)
- [ ] 若采用隔离而非根除,代码注释写明原因与复现方式
- [ ] **未通过放宽断言或自动重试来掩盖**
- [ ] 前端测试不受影响(回归)

- 测试框架更换
- 性能优化
