## 1. 背景与目标

### 1.1 缺陷一:注释说白名单,代码是全继承

`packages/callback-agent/src/command-driver.ts` 第 47–48 行:

```ts
// Build environment: explicit allowlist only, no secret inheritance
const env = driver.env ? { ...driver.env } : undefined;
```

**注释与代码正好相反。** 未配置 `driver.env` 时传 `undefined` 给 spawn ——
Node 的语义是**继承父进程的完整环境变量**,包括所有密钥。

也就是说:**默认路径上没有任何白名单**,注释里那句
"no secret inheritance" 在默认配置下是假的。

⚠️ 这条注释的危害不止于「没实现」:它会让读代码的人**以为已经安全了**,
从而不去检查。**一句错误的安全注释比没有注释更坏。**

### 1.2 缺陷二:默认超时(60s)长于默认租约(30s)

`packages/callback-agent/src/config.ts`:

| 项 | 行 | 默认值 |
|---|---|---|
| `leaseMs` | 123 | **30000**(30 秒) |
| `defaultTimeoutMs` | 124 | **60000**(60 秒) |

**当前未见续租。**

于是默认配置下:命令跑到第 30 秒租约过期 → 事件回到可认领状态 →
**第二个消费者认领并再跑一次同一条命令** —— 而第一条还在跑。

R9 原文:「长于初始 lease 的命令在双消费者下不会无保护地重复启动」。
**默认值本身就构成这个场景**,不需要任何异常配置。

### 1.3 目标

1. 环境继承变成**真正的显式白名单**,实现、配置、文档三处一致;
2. 命令执行时间与租约的关系**有明确保护** —— 续租,或限制两者关系。

## 3. 详细改动

### R1. 显式白名单

未配置时**不继承任何东西**,或只继承一个**写死的最小集合**
(例如 `PATH` / `HOME` 之类命令跑起来必需的)。

- 若采用最小集合,**在代码里写死并注释说明每一项为什么必需** ——
  不要做成可配置的,那等于又开了口子;
- 白名单**必须是名单本身**,不能是「除了这些之外都继承」的黑名单。

⚠️ **注释必须与代码一致**。如果最终实现有任何折衷,改注释去匹配实现,
不要留下 §1.1 那种反向注释。

### R2. 白名单要能配

宿主要能声明「这条命令需要 `HTTPS_PROXY`」。配置项的形状自选,
但要在文档里给一个**完整可抄的示例**。

### R3. 租约与超时的关系必须有保护

两条路线,**自选其一并说明理由**:

- **(a) 续租**:命令仍在跑时按周期续租。
  续租失败的处置要明确 —— R9 原文:
  「**不把未知结果直接等同执行失败**」。
  也就是说续租失败不等于命令失败,要有区分。
- **(b) 限制关系**:强制 `defaultTimeoutMs < leaseMs`(启动时校验,
  不满足就拒绝启动并说明),让命令不可能活过租约。

**(b) 更简单,(a) 更实用。** 你判断,但要在汇报里写清取舍。

⚠️ 无论选哪条,**默认配置必须自洽** —— 不能改完还是 30s 租约配 60s 超时。

### R4. 环境继承的验证只用哨兵变量

R9 原文:「**仅使用测试环境哨兵变量检查继承**」。

即:在测试里设一个 `COAGENTHUB_TEST_SENTINEL=...` 之类的变量,
断言它**没有**出现在子进程里。

⚠️ **不要在测试里读、打印或断言任何真实密钥**,
也不要为了证明「没继承」而去枚举 `process.env` 的内容。

## 4. 验收标准

**基线先用工具取**(callback-agent 包的测试目录自行确认):

```
node scripts/test-baseline.mjs packages/callback-agent <相关测试文件...>
```

1. **核心一:默认不继承**。未配置 env 时,哨兵变量**不出现**在子进程环境里。
   ⚠️ **这条用例改动前必须是红的** —— 给出改前的实际报错。
2. **白名单生效**:配置了 `HTTPS_PROXY`(或你选的示例项)时,
   子进程**能**拿到它,且**只**拿到白名单里的。
3. **核心二:命令不会活过租约无保护**。
   构造「命令执行时间 > 初始租约」的场景 + **双消费者**,
   断言同一条命令**不会被启动两次**。
   ⚠️ 这条同样**改动前必须是红的**(当前默认值就构成该场景) ——
   给出改前的实际现象。
4. **续租失败的处置**(若选 a):断言续租失败**不被当成执行失败**,
   给出实际的状态流转。
5. **默认值自洽**(若选 b):启动时校验生效,给出不满足时的实际错误输出。
6. **文档同步**:配置文档里有可抄的白名单示例,
   且 §1.1 那句反向注释已消失。在汇报里贴出改后的注释原文。
7. 定向测试前后对照,失败数不增加。
8. `npx tsc --noEmit -p tsconfig.json` 通过(callback-agent 包的 tsconfig)。

## 5. 不涉及的改动

- **不改宿主侧 eventId 幂等责任**(R9 原文保留)。
- 不改 claim/ack/fail 端点(服务端,已 Landed)。
- 不改事件信封结构。
- 不引入认证或加密。

## 6. 兼容性

- **行为变更(需显著写明)**:此前未配 env 的驱动**能拿到 server 的全部环境变量**,
  改后拿不到。
  ⚠️ **依赖这一点的既有配置会坏** —— 例如靠继承拿代理变量的命令。
  这正是本票要治的问题,**不予兼容**,但必须在汇报里
  **明确列出升级后需要显式配置什么**,让使用者能照着改。
- 若选 (b),原本合法的「超时 > 租约」配置将拒绝启动 —— 同样要在汇报里写明。
