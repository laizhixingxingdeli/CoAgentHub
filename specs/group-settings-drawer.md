# Spec: 群设置改为抽屉,不再是一条需要「返回」的岔路

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-23
> **修正**: `specs/remove-context-panel-and-settings-page.md` 的形态选择
> (该票把设置从右栏搬到独立页是对的方向,但整页太重)

## 背景

`remove-context-panel-and-settings-page`(`d4c7826`)把群设置从右栏 tab 搬到
`/groups/:id/settings` 整页。搬离右栏是对的——一栏 160–320px 填不了绝对路径、
编辑不了分工提示词。但**整页偏重了**:

**内容量撑不起一整页。** 浏览器实测:基本信息只有一个输入框 + 归档按钮,
项目绑定一个输入框 + 解绑。真正有分量的只有成员表格。

**页面自己给出了证据:顶部那个「← 返回消息流」链接。**
一个需要「返回」的地方,说明它是条岔路——你在看任务跑到哪,想改个执行器的
分工提示词,得跳走、改完、跳回来、重新找回刚才看的那条需求。

**使用频率天差地别。** 群名 / 项目路径 / 归档是建群时设一次基本不动的;
成员分工偶尔调;而任务在持续发生。把一次性配置放进需要跳转的页面,
代价是每次都要跳。

---

## 要求

### R1. 默认交互改为右侧抽屉

- 群详情页标题栏的齿轮改为**打开抽屉**,不再导航
- 抽屉从右侧滑出,遮罩层之上,**不卸载**底下的群详情页——关闭后仍在原来那条需求上
- 宽度自行判断(参考量级 480px);移动端应当可用(全宽或近全宽)
- 关闭方式:遮罩点击 + 关闭按钮 + `Esc`,三者都要有

### R2. 路由保留,两种形态共用同一组件

`/groups/:id/settings` **不要删**——它承担深链接:分享给别人、刷新后仍在原处。

- 直接访问该 URL → 渲染成整页(现有形态)
- 从群详情页点齿轮 → 渲染成抽屉
- **两者必须共用同一份内容组件**,不得出现两套实现
  (那正是「右栏任务 tab 与主区重复渲染」的老毛病)
- `/groups/:id/members` 的重定向保持不变

### R3. 成员列表适配窄容器

现有成员表格有「名称 / 设备 / 角色 / 分工 / 操作」五列,480px 放不下。

- 抽屉形态下改为**卡片/列表行**呈现,不用表格
- 整页形态下保留表格还是也改成列表,自行判断——但**倾向统一**,
  两种形态维持两套呈现会重蹈覆辙
- 「分工」字段较长,现有的「展开」交互保留

### R4. 编辑不能丢

抽屉里的编辑(改群名、改路径、改角色、改分工)与整页形态**能力完全一致**。
关闭抽屉时若有未保存的编辑,给出提示,不要静默丢弃。

## 验收标准

- [ ] 群详情页点齿轮打开抽屉,**不发生页面导航**
- [ ] 关闭抽屉后仍停留在原来选中的那条需求上(底层页面未卸载)
- [ ] 遮罩点击 / 关闭按钮 / `Esc` 三种关闭方式都可用
- [ ] 直接访问 `/groups/:id/settings` 仍渲染整页
- [ ] 两种形态共用同一内容组件,**无两套实现**
- [ ] `/groups/:id/members` 重定向不变
- [ ] 抽屉内成员列表在窄容器下可读,不出现横向滚动或文字挤成一列
- [ ] 抽屉内可完成全部编辑(群名 / 项目路径 / 归档 / 加成员 / 改角色 / 改分工 / 移除成员)
- [ ] 有未保存编辑时关闭会提示
- [ ] 移动端宽度下抽屉可用
- [ ] 新增测试覆盖:抽屉开关、底层页面未卸载、深链接整页渲染、共用组件、未保存提示
- [ ] `pnpm --filter @laizhixingxingdeli/web test` 全绿(先跑一次确认基线,不得减少)
- [ ] `pnpm --filter @laizhixingxingdeli/web build` 通过

## 不涉及

- **不改**后端、不加接口
- **不改**设置项本身的内容与校验(`PATCH /groups/:id` 行为不变)
- **不改**群列表页的重命名 / 归档(两边都留,是既定决策)
- 不引入新依赖(项目已有的 UI 组件库里应有 Sheet/Drawer;若确实没有,
  在汇报里说明再定,**不要擅自装包**)
