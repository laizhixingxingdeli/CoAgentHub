# Spec: PID 文件丢失时 restart 静默空转,却报告成功

> **状态**: Landed — L3 通过(2026-08-28)
> **版本**: 1.0
> **日期**: 2026-08-27

## 现象

`scripts/coagenthub-prod.sh restart` 在 PID 文件丢失或与实际进程不符时
**什么都不做,却以成功退出**:

```
$ bash scripts/coagenthub-prod.sh restart
SKIP  server  :3001 已被占用 (pid 31743),跳过
OK    web     :3000 就绪
$ echo $?
0
```

服务端进程始终未被替换。实测后端进程自 **20:35:11 起连续存活近 3 小时**,
期间检视者执行过多次 `build + restart`,**全部为空操作**,
`/api/health` 一直是旧构建。

## 根因

```
cmd_stop  (:161)  只杀 PID 文件($PIDFILE = /tmp/coagenthub-prod-3001.pid)里记录的进程。
                  文件不存在或 pid 对不上 → 打印「没有由本脚本启动的进程」→ 静默返回
cmd_start (:127)  发现端口已被占用 → 「SKIP :3001 已被占用」→ 跳过启动
cmd_restart(:184) = cmd_stop + cmd_start → 整体空转,退出码 0
```

PID 文件会在多种正常情况下失准:手工 `kill`、进程被其他方式拉起、
`/tmp` 被清理、系统重启等。

## ⚠️ 危害:让所有「重建后验证」不可信

本轮已造成两次误判 —— 检视者在旧构建上采样,先后错误地判定
「atomcode 碎片修复无效(45.5%→59.8%)」与「孤儿收敛竞态修复无效」,
两次都要重新取证才发现是运行时未更新。

同类问题亦解释了看门狗日志中的
`FAIL 重建失败(连续 1 次)`(见 `rebuild-when-runtime-goes-stale` findings):
`restart --build` 实际未替换进程。

## 要做的

### R1 — stop 必须以「端口上实际监听的进程」为准

PID 文件仅作**加速路径**。文件缺失或与实际不符时,
必须回退到按端口查实际监听进程(脚本已有 `port_pid` 函数)并停止它。

⚠️ 只停本项目的目标端口($SERVER_PORT / $WEB_PORT),不得波及其他进程。

### R2 — ⚠️ start 的「端口占用则跳过」不得掩盖 stop 失败

`cmd_start` 的跳过逻辑对**幂等启动**是合理的,保留。
但在 `restart` 语义下,stop 之后端口**仍被占用**属于异常,
必须**报错并以非零退出码结束**,不得报告成功。

### R3 — restart 需确认进程确实被替换

停止后等待端口释放;启动后确认新进程 pid **不同于**停止前的 pid。
未替换成功 → 非零退出并给出可读原因。

### R4 — ⚠️ 不得用 `pkill -f node` 之类的粗暴匹配

会误杀开发者的其他 node 进程(本机同时跑着多个 agent 与工具链)。
按端口定位是唯一可接受的回退方式。

### R5 — 范围限制

只改 `scripts/coagenthub-prod.sh`。
⚠️ 不改看门狗脚本(它调用本脚本,修好后自然受益),
不改服务端代码,不改结案守卫。

## 验收要点

- 删除 PID 文件后跑 `restart`,验证:进程**确实被替换**(贴出前后 pid 与启动时刻)
- `restart` 后 `/api/health` 的 `stale` 变为 `false`(贴出前后输出)
- 构造「stop 后端口仍被占用」的情形,验证 **非零退出 + 可读报错**(R2)
- PID 文件正常存在时,行为与现状一致(不回归)
- ⚠️ 验证**未误杀**目标端口之外的进程(R4)
- `stop` / `start` 单独调用仍幂等
- 如脚本有测试则全绿并贴出用例数;无测试则说明如何验证
