# Spec: 改守卫的票,没法用旧守卫结案

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-26

## 现象:一次真实的引导死锁

修正票 `01a039f7` 的汇报原文:

> 实现已完成并提交 `28825b6a`,源码/测试均通过;但 localhost:3001 仍运行旧 build
> (`GET /api/health` 返回 `stale=true`),因此**旧版 zero-child guard 拒绝了合法
> `alreadySatisfied` 回写**。按票面禁止在执行窗口内重启后端,无法通过当前运行时
> 完成 done 回写。

它没做错任何一步:代码写对了、测试跑绿了、如实汇报了、也遵守了「不要在执行窗口内
重启后端」。**但它无法结案。**

## 根因:结案守卫由「正在运行的构建」执行

凡是改动 `assertCoordinationCloseIntegrity` 一带的票,都有这个性质:

```
新守卫在源码里  →  但结案走的是旧构建里的旧守卫  →  合法回写被拒
```

而「不在执行窗口内重启后端」这条约束是对的(重启会把在途任务打成失败,
本轮已有过教训),**两条正确的规则叠在一起,产生了一个谁都没做错的死锁。**

⚠️ 这不是一次性问题:队列里还有 `close-requires-terminal-children`、
`l1-bypass-must-be-visible` —— **都改结案守卫,都会撞上同一堵墙。**

## 决策:让「因旧构建被拒」成为可识别、可恢复的状态

### R1. 拒绝信息要点明「可能是旧构建」

`assertCoordinationCloseIntegrity` 抛出的每一条 400,在**运行时陈旧**
(`runtime.stale === true`)时,追加一句:

> 注意:当前运行时为陈旧构建(staleReason: <reason>),本次拒绝可能来自旧版守卫;
> 若已在源码中修改结案规则,请在发起方重启后重试回写。

陈旧判定**复用** `lib/runtime-status.ts` 的现有派生,**不另写**。

⚠️ 只是**追加说明**,不改变拒绝与否的判定 —— 陈旧不是放行理由。

### R2. 协调者任务书:遇到这种拒绝该怎么做

协调者任务书模板增加一行:结案被拒且运行时陈旧时,**不要**反复重试、
**不要**改代码去迎合旧守卫、**不要**自行重启后端;
应以 `failed` 结案并在 `error` 中写明「实现已提交 <hash>,因旧构建守卫拒绝回写」,
由发起方重建后处理。

⚠️ 本轮协调者**已经自发做对了这件事**(汇报原文见上)。把它固化下来,
不依赖某次运气。

### R3. 发起方侧:提供一个可查的信号

任务详情响应中,当任务 `failed` 且 `diffSummary.error` 存在、
且该任务终态时刻运行时陈旧时,透出 `staleBuildSuspected: true`。

这样检视者/发起方能**一眼区分**「真失败」与「因旧构建卡住,重建后可继续」。

⚠️ **不做**自动重启、**不做**自动重试 —— 重启时机必须由发起方掌握
(在途任务会被重启打成失败,这是硬约束)。

### R4. 不改这些

- **不改**任何守卫的判定逻辑(本票只加说明与信号)
- **不改**「不在执行窗口内重启后端」这条约束
- **不做**自动重建/自动重启/自动重试(R3)

## 验收标准

- [ ] 运行时陈旧时,结案 400 的信息含「可能来自旧版守卫 + 请重启后重试」
- [ ] 运行时**不**陈旧时,400 信息**逐字不变**(回归,必测)
- [ ] 陈旧不改变拒绝与否的判定(相同输入,陈旧与否结果一致,必测)
- [ ] `failed` + 终态时运行时陈旧 → 任务详情透出 `staleBuildSuspected: true`
- [ ] 其余情况下该键**不出现**
- [ ] 协调者任务书含 R2 那行
- [ ] 陈旧判定复用 `runtime-status.ts`(读代码确认,不另写)
- [ ] 后端测试全绿,贴出用例数

## 不涉及

- 守卫判定逻辑(R4)
- 自动重启/重试(R3,明确不做)
- 前端展示

## 执行环境提示

- 实现位置:`routes/group/tasks.ts` 的 `assertCoordinationCloseIntegrity`
  与任务详情组装处;陈旧判定在 `lib/runtime-status.ts`
- ⚠️ 本票**必须下发给执行器**完成
- ⚠️ 本票自身也可能撞上它描述的死锁 —— 若结案被旧构建拒绝,
  按 R2 的做法以 `failed` 结案并写明,由检视者重建后处理,**不要**自行重启后端
- ⚠️ 做完记得提交
