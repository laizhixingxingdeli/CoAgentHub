# Spec: 仓库改了 skill,已安装副本不会跟上

> **状态**: Landed — L3 通过(2026-08-24),实现 `93fd3152`
> **版本**: 1.0
> **日期**: 2026-08-24
> **严重度**: 高 —— 本轮最大事故的直接成因就是这一类不同步

## 背景

`skills/` 下四份 skill 是**唯一事实来源**,但各 agent 实际读的是自己 runtime 目录
里的**安装副本**:

```
~/.claude/skills/coagenthub-reviewer/SKILL.md
~/.codex/skills/coagenthub-coordinator/SKILL.md
~/.atomcode/skills/coagenthub-executor/SKILL.md
~/.codebuddy/skills/coagenthub-executor/SKILL.md
```

**两者之间没有任何同步机制。** 仓库里改了 skill,安装副本原样不动,直到有人
手工拷贝。本轮就发生过:`executor-switch-task-identity` 改了协调者 skill §2.2,
提交进仓库,而 `~/.codex` 的副本计数仍为 0 —— 是检视者在验收时顺手发现并补拷的。

**没人查就永远不同步。**

### 为什么这不是小事

本轮最大的事故——协调者拿着执行器任务书干活、L1 层从未发生、L2 退化成自审、
16 张票全部误判——根子是**平台发的指令与 skill 说的不一致**。skill 不同步是
同一类问题的另一个入口:agent 拿着旧规矩干活,而且**看不出来**。

skill 内容本身不携带版本,agent 也不会声明自己读的是哪一版,所以这种偏差
**没有任何征兆**,只能靠事后从行为反推。

## 决策:平台提供比对与同步,不做自动覆盖

### R1. skill 内容带上可比对的指纹

`GET /api/skills/{role}` 的响应增加 `version` 字段,取值为该 skill 文件内容的
**内容哈希**(sha256 前 12 位即可)。

- 哈希由**文件内容**算出,不依赖 git —— 打包后的 dist 里没有 .git
- 响应体的其余字段**保持不变**(回归)

### R2. 新增比对接口

`GET /api/skills/{role}/digest` 或在现有响应里已足够 —— **由执行者选择形态**,
但必须能让调用方**不下载全文就拿到指纹**(skill 文件不小,轮询全文是浪费)。

### R3. 提供一个同步命令

新增脚本(建议 `scripts/coagenthub-sync-skills.mjs`),行为:

- 扫描已知的 runtime skills 目录(与 `project-onboarding-interactive` R6 同一张表,
  **复用同一份目录约定,不要各写一份**)
- 对每个找到的 `coagenthub-<role>/SKILL.md`,算内容哈希,与平台指纹比对
- **默认只报告差异,不写文件**(`--check` 语义)
- 加 `--write` 才真正覆盖,并逐条输出「已更新:<路径>」

**默认不写**的理由:静默覆盖别人机器上的文件是危险动作,而且用户可能有意改过
本地副本。让差异**先可见**。

### R4. 不做自动同步

**不要**做定时轮询、启动时自动拉取、或任务下发前强制刷新。理由:

- 下发前刷新会在关键路径上引入网络与文件写入,失败时污染任务;
- 自动覆盖会掩盖「有人手工改了本地 skill」这个信号 —— 而那个信号本身有价值;
- 本平台是 LAN 单机部署,手工跑一次同步命令的成本远低于自动机制的复杂度。

**目标是让不同步变得可见且易修,不是让它不可能发生。**

### R5. 不改 skill 内容,不改任务书自助路径

- `skills/` 下四份文件的**内容不动**
- 任务书模板的「未安装 → 先 GET 再装」自助路径**保留**(那是首次安装的安全网,
  与本票解决的"已装但过期"是两个问题)

## 验收标准

- [ ] `GET /api/skills/{role}` 响应含 `version`(内容哈希),其余字段未变(回归)
- [ ] 同一份 skill 内容 → 哈希稳定;内容改一个字 → 哈希变化
- [ ] 哈希由文件内容算出,**不依赖 git**(打包后仍可用)
- [ ] 同步命令默认**只报告不写文件**
- [ ] `--write` 才覆盖,且逐条输出已更新路径
- [ ] 本地副本与平台一致时,报告「已是最新」且不写文件
- [ ] runtime 目录不存在时**跳过并列出**,不创建目录
- [ ] runtime 目录约定与 `project-onboarding-interactive` R6 **复用同一份定义**,
      未各写一份
- [ ] 未新增任何自动轮询/启动时拉取/下发前刷新(R4)
- [ ] `skills/` 下文件内容未被改动
- [ ] 测试全绿,贴出用例数

## 不涉及

- 自动同步(R4 明确不做)
- skill 内容本身
- 首次安装(归 `project-onboarding-interactive` R6)

## 执行环境提示

- 本仓 pnpm 项目
- 已知 runtime 目录(本机实测存在):`~/.claude` `~/.codex` `~/.atomcode` `~/.codebuddy`
- 测试**不要**真的写用户 home 下的目录 —— 目录根应可注入,测试里指向临时目录
