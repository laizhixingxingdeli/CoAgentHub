# Spec: 执行器接入向导(批3)——自动推断画像,用户只点确认

> **状态**: Draft — 待批2 落地后冻结
> **版本**: 0.1
> **日期**: 2026-08-29
> **ADR**: [ADR-0008](../docs/adr/0008-executor-adaptation-config-over-code.md)
> **依赖**: [executor-output-profile.md](executor-output-profile.md)(批2)

## 1. 目标与理由

批2 让画像可配,但**不能让用户手写画像**。手写的失败模式很难看:填错一个字段路径
→ 所有行落 raw 兜底 → 缓冲顶满,正好回到要治的那个 bug,而且没人知道是配错了。

向导把「手写 JSON 路径」变成「看真实输出、点确认」:填 bin → 平台跑一次最小任务
→ 从实际输出**自动推断**画像 → 并排预览 → 确认接入。手写只是异常路径。

## 2. 流程

1. 用户在接入界面填 `bin` 与 args 模板,点「探测」。
2. 平台在受控临时目录内跑一个 canned 最小任务(内容固定、不改仓库、只调用一次
   只读工具),捕获 stdout/stderr。
3. 推断画像(见 §3)。
4. 预览页并排展示:
   - `原始 N 行 / M 字节 → 摘要 K 行`,压缩比
   - 解析出的动作行(`[工具]` / `[命令]` / `[汇报]`)实样
   - token 字段命中值:`input / output / cached / total` + 聚合方式
   - `parseTaskReport` 能否解析五段汇报
5. 用户确认 → 写入 `executor_config`(含 `output_profile`)。不满意 → 就地改某个
   路径,实时重算预览。

## 3. 推断启发式(全部可被用户覆盖)

| 推断项 | 依据 |
|---|---|
| `format` | 首若干行能否 `JSON.parse` |
| `discriminator` | 出现率最高、取值为短字符串枚举的顶层字段(通常是 `type`) |
| 增量噪音 | 字段名匹配 `/delta$/`,且流中存在同名 `/end$/` 携带完整正文 → 进 `skip` |
| 工具事件 | 键名匹配 `/tool/i` 且同时带 name 与 args 形态的字段 |
| `usage` 位置 | 扫出带 input/output 形态键名的对象 |
| `usage.aggregate` | **同一流内多次出现的 usage 数值是否单调递增**:递增 → `last`;各自独立 → `sum` |
| `finalText` | 最后一条 assistant 角色消息的文本块 |

`aggregate` 那条是本向导最有价值的一项 —— pi 的 usage 是每消息独立、不累计,
通用扫描「取最后一个」会系统性少报(实测:两轮 3654+166,只报 166)。这个坑
靠人眼看不出来,靠单调性判别一次就判出来了。

## 4. 安全边界

canned 探测任务会在用户机器上**真实执行一个 agent CLI**,必须有边界:

- 在临时工作目录内跑,不指向用户仓库。
- 任务内容固定、只读(如「列出当前目录并回复 done」),不由用户自由输入。
- 超时上限 + 输出字节上限,超限即杀并如实报告。
- 探测结果只写画像,不写任何凭据;env 变量按名引用,值不入库、不回显。

## 5. 验收标准(草案)

1. 对 pi 执行探测:自动推断出的画像,其解析结果与批2 手写画像的输出**一致**;
   `aggregate` 被判为 `sum`。
2. 对 codex / codebuddy 执行探测:推断画像的解析结果与既有用例期望一致。
3. 探测一个不存在的 bin:给出 `spawnFailureHint` 的可操作提示,不产生半截配置行。
4. 探测超时 / 输出超限:如实报告,不静默截断成一份"看起来正常"的画像。
5. 用户改一个路径:预览实时重算,不需要重跑探测。

## 6. 不涉及

- 不做画像的版本管理 / 回滚(如需,另开)。
- 不做远端(a2a)执行器的探测 —— 它们没有本地 stdout。
- 不自动接入:推断结果永远需要用户确认后才落库。
