# Spec: 主区宽度没扣掉侧栏,笔记本宽度上整页横向溢出

> **状态**: Landed — L3 通过(2026-08-26),实现 `ad3a7008`
> **版本**: 1.0
> **日期**: 2026-08-26

## 现象:溢出量恒等于侧栏宽度

群组详情页(`/groups/:id`)在常见笔记本宽度上整页横向溢出。实测:

| 视口 | 侧栏 | `main.left` | `main.width` | 页面横向溢出 |
|---|---|---|---|---|
| 1024 | 256 | 256 | **1024** | **256** |
| 1280 | 256 | 256 | **1280** | **256** |
| 1440 | 256 | 256 | **1440** | **256** |
| 1536 | 256 | 256 | **1536** | **256** |
| 1680 | 256 | 256 | 1570 | 146 |
| 1920 | 256 | 256 | 1656 | 0 |
| 2560 | 256 | 256 | 2296 | 0 |

`main` 起点在侧栏之后(`left = 256`),宽度却直接取了**整个视口宽**,
于是右边界 = 视口 + 256。**溢出量恒等于侧栏宽度**,这就是根因的指纹。

1920 以上溢出为 0 不是因为布局正确,而是**内容本身撑不到那么宽**,
问题被内容尺寸掩盖了。

## 后果

1280 的笔记本上,右侧的「展开」按钮与三层时间线的 **L3 节点根本不可见**,
要横向滚动整页才够得到。本仓库 `docs/assets/quickstart-*.jpg` 第一版重拍
就是这样被截掉的。

## 这不是宽度铺满那一票引入的

已验证:在当前构建上用脚本把旧的 `max-w-[1440px]` 注入回该容器,
文档宽仍是 1536 —— **与修复前完全相同**。
`group-detail-should-fill-width` 只动了容器的宽度上限,没有制造本问题。

⚠️ 但那张 spec 的验收标准里写了「无横向滚动条」,当时只在 2560px 下验证,
而 2560 恰好是问题被掩盖的档位。**验收面太窄是检视者的疏漏**,与实现无关。

## 决策

### R1. `main` 的宽度必须扣掉侧栏

`main` 当前带 `w-full`(= 父级 100%,而父级是视口宽的 flex 行),
与它 `flex-1` 的定位冲突。让 `main` 由 flex 分配剩余空间即可,
不要再用 `w-full` 强制成满宽。

⚠️ **不要**用 `calc(100vw - 256px)` 之类把侧栏宽度写死 —— 侧栏可折叠,
宽度写死会在折叠态再错一次。让 flex 自己算。

### R2. 侧栏折叠态必须一并验证

侧栏支持折叠。展开与折叠**两种状态**下都不得出现横向溢出。

### R3. 不改侧栏本身

不改侧栏宽度、不改它的 `md:` 断点行为、不改折叠交互。本票只改主区取宽方式。

### R4. 不动内容区内部布局

不改三层时间线、需求列表、上下文面板的任何内部尺寸与比例。
它们在正确的可用宽度下本就能正常排布 —— 本票只把可用宽度给对。

## 验收标准

- [ ] 1024 / 1280 / 1440 / 1536 / 1680 四档以上视口:
      `document.documentElement.scrollWidth` **等于** 视口宽(溢出 0,必测)
- [ ] 同样各档下 `main` 的右边界**不超过**视口右边界(必测)
- [ ] 1280px 下三层时间线的 **L3 节点与右侧「展开」按钮可见**,无需横向滚动
- [ ] **侧栏折叠态**下各档同样溢出 0(R2,必测)
- [ ] 1920 / 2560 下的布局与改动前一致(回归 —— 这两档原本就是 0,不得变坏)
- [ ] 实现中**没有**写死的侧栏宽度数值(如 `100vw - 256px`,读代码确认)
- [ ] 前端测试全绿,贴出用例数

## 不涉及

- 侧栏自身的宽度与折叠行为(R3)
- 内容区内部布局与比例(R4)
- 界面 i18n 词典缺失(另票)
