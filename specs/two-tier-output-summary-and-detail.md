# Spec: 实时输出分两层 —— 摘要看「在做什么」,明细按需展开

> **状态**: Frozen — 待实现
> **版本**: 1.0
> **日期**: 2026-08-27

## 背景

`generic-executor-output-parsing`(已 Landed `6de49213`)解决了「新 agent 顶满缓冲」,
但当前仍是**一条扁平字符串**:摘要和明细混在一起,只能整体截断。

实测思考过程占缓冲的绝大部分:

```
01a03eca  AtomCode    95.3%
01a03f23  AtomCode    89.5%
01a03f35  AtomCode    84.5%
01a03f15  CodeBuddy   64.0%
01a03ee9  CodeBuddy   41.3%
```

需求:**正常只需知道 agent 在做什么;具体输出可以展开看到**。
思考不能直接丢弃 —— 本轮多次排障正是靠它定位
(例:查协调者空转,取证为「全程只 wc -l SKILL.md,从未读取 §2.3」)。

## 决策:摘要流 + 明细存储

### R1 — 解析器产出结构化条目,不再是纯字符串

现接口 `(chunk: string) => string` 改为产出条目序列,每条至少包含:

```
id       任务内单调递增的短标识(如 t7),供展开引用
kind     thinking / tool / command / result / report / error / raw
summary  一行摘要,进摘要流
detail   可选,完整原文,进明细存储
```

⚠️ 这是**有意的破坏性接口改动**,三个定制分支与通用解析器都要跟着改。
既有渲染口径(`[工具]`/`[命令]`/`[汇报]`)保持不变,只是多带 `#id`。

### R2 — 摘要行必须说明「在做什么」,不是「有多少」

⚠️ thinking 的摘要**取要旨,不取字数**。

```
✅  [思考 #t7] 先确认守卫在哪个文件,再决定改哪一段
❌  [思考 #t7] 3 段,共 4820 字
```

取首句或前 N 字并截断即可,不要求语义总结。

### R3 — 折叠范围

```
折叠(摘要 + 明细)  thinking、工具结果全文、命令输出全文、超长参数值
不折叠(仅摘要)      工具名 + 参数键名、命令行本身、简短汇报
⚠️ 永不折叠         错误信息 —— 出问题时最不该藏起来的就是它
```

### R4 — 明细存磁盘,不进内存也不进 diffSummary

⚠️ 不放内存(无界增长),不放 `diffSummary`(撑大数据库行)。
按任务写 JSONL 文件,沿用仓库既有惯例(prod 日志即 `/tmp` 按天 + 14 天清理):

```
/tmp/coagenthub-task-detail-<taskId>.jsonl
{"id":"t7","kind":"thinking","at":"...","text":"完整原文"}
```

⚠️ **明细必须在任务终态后仍可读** —— 内存缓冲照常释放,但文件保留,
供事后排障。保留期与清理沿用 prod 日志的 14 天口径。

### R5 — 展开 API

```
GET /groups/:gid/tasks/:tid/output/:entryId    单条明细
GET /groups/:gid/tasks/:tid/output?detail=1    整份明细
```

⚠️ 权限与现有 `includeOutput` 一致,不得放宽。
⚠️ 单条明细找不到时返回 404 并说明原因(条目已被清理 / id 不存在),不得静默返回空。

### R6 — 摘要流仍受现有上限约束

摘要进现有环形缓冲(1000 行 / 256KB)不变。
⚠️ 折叠后摘要行显著变短,该上限应能容纳远多于此前的动作条数 ——
这正是本票的收益,不要因此放宽上限。

### R7 — ⚠️ 不得回归既有能力

- 解析失败的行仍逐字保留(历次 R3 硬要求)
- 未知 executorKey 仍走通用解析器并只记一次观测日志
- 定制分支的渲染准确度不得下降

## 验收要点

- 新起一条真实任务(AtomCode 或 CodeBuddy),运行中采样:
  **摘要流字节数较改造前同类任务下降至少一个数量级**
  (参照实测:AtomCode 59191B / 76744B,CodeBuddy 182198B)
- 同一采样中每条 thinking 摘要**是一句要旨而非字数统计**(贴出样例行)
- 按摘要行里的 `#id` 调展开 API,能取回**完整原文**(贴请求与响应片段)
- 任务进入终态后再调展开 API,**仍能取回明细**(必测,证明脱离内存缓冲)
- 错误信息未被折叠(必测)
- 解析失败的行逐字保留;未知 key 仍只记一次日志(R7)
- 测试全绿,贴出用例数;**基线 739**
