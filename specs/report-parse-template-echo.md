# Spec: 汇报解析误把任务书模板占位符当成执行器汇报

> **状态**: Landed — 已完成(2026-08-23 核实)
> **版本**: 1.0
> **日期**: 2026-08-22
> **协作模式**: 两层（协调者兼任写 spec，spec v3.8 §3.14）

## 背景（实测复现，不是设想）

2026-08-22 走平台下发一个最小验证任务，执行器（codex）实际输出了
`PROXY_TEST_OK`，但平台解析出来的汇报是：

```
summary : <做了什么,3-5 句>
tests   : <测试结果摘要>
todo    : <未完成事项,无则写"无"> | 本群分工:角色=[executor];提示词=… | ## 执行与测试要求 | …
```

群消息卡片因此显示为一堆占位符，**汇报等于失效**。

## 根因

`packages/backend/server/src/lib/executor-task/report.ts` 的 `parseTaskReport`
扫描**整个 stdout** 找段头（`^\s*(?:汇报|report|summary)\s*[:：]`），取**第一个匹配**。

而执行器的 stdout 里包含**任务书全文的回显**——codex 执行时会 `sed -n '1,260p' <ticket>`
把任务书打印出来。任务书里的「汇报格式」小节恰好含有同样的段头：

```
汇报: <做了什么,3-5 句>
测试: <测试结果摘要>
```

这些占位符**先于**执行器真正的汇报出现，于是被当成了结果。

`todo` 段更严重：它一路吞到下一个段头为止，把平台注入的「本群分工」「执行与测试要求」
整段都收了进去，说明段落边界判断在有回显时完全失准。

## 为什么现在才暴露

直调 CLI 时执行器一般不回显任务书（任务书由 `-p` 参数直接传入）；
走平台下发时任务书落在临时文件里，执行器**必须读它**，读了就会回显。
所以这是**只有走平台才会触发**的缺陷。

## 改动范围

`packages/backend/server/src/lib/executor-task/report.ts` 的 `parseTaskReport`。

核心要求：**在有任务书回显的情况下，仍能取到执行器真正的汇报。**

具体策略由实现者判断，以下是可考虑的方向（不强制，选你认为最稳的，并说明理由）：

- **取最后一组而非第一组**：真正的汇报总在输出末尾，回显在前面。
  但要注意执行器可能多次回显，或汇报后还有别的输出。
- **占位符识别**：值形如 `<...>` 的整体视为未填写的模板，跳过。
  简单直接，但只挡得住这一种模板写法。
- **段组完整性**：真正的汇报是连续出现的一组段（提交/测试/汇报/遗留），
  以「最靠后的完整段组」为准。
- **划定解析窗口**：只在输出末尾 N 行内找段头。
  与既有的「老格式回退取末尾 15 行」逻辑一致，但 N 要够大。

⚠️ **必须保留的既有行为**（`report.ts` 注释与现有测试里都有）：

- 老格式自由文本输出的回退解析（`legacyExtractSummary`）
- 提交段只取首个 7~40 位 hex token，非 hex 则省略（避免描述性文字当 hash 落库）
- 提交段缺失时回退全量输出提取 hash
- `tokenUsage` 段只取清洗后的纯数字

## 验收标准

- [ ] 给定「任务书回显（含模板占位符）+ 执行器真实汇报」的 stdout，
      解析结果取到**真实汇报**，不是占位符
- [ ] `todo` 段不再吞入任务书回显的后续内容（分工说明、执行要求等）
- [ ] 上述四条既有行为全部不变，原有测试不改断言即通过
- [ ] 新增测试用**真实复现样本**：任务书回显在前、真实汇报在后
- [ ] 新增测试覆盖「执行器完全没输出汇报段」的情况（不得把回显的占位符当汇报）
- [ ] `pnpm --filter server test` 全绿（基线 29 文件 / 382 用例）

## 不涉及

- **不改**任务书模板本身（改模板只是绕开，回显问题依然存在，
  换个执行器、换种回显方式又会复现）
- **不改**前端
- **不改**执行器 skill
- 不引入新依赖

## 测试环境提示

这台机器负载高，全量并行跑测试会偶发超时且失败文件漂移。
判断是否真回归请用串行：`pnpm --filter server exec vitest run --maxWorkers=1`。

**另注**：codex 执行器在平台 spawn 时带 workspace-write 沙箱，
**禁止监听 127.0.0.1 且禁止写 `.git/`**。因此：
- 需要起本地服务的测试会报 `listen EPERM` —— 这是环境限制不是回归，
  **全量测试由协调者代跑**，执行器只需跑定向测试与类型检查
- 执行器**无法自行 git commit**，需申请非沙箱操作

## 清理核实记录(2026-08-23)

检视者核实:`lib/executor-task/report.ts:118-119` 已有占位符段跳过逻辑,注释写明「执行器可能先回显完整任务书,其中的结构化汇报段是模板占位符……忽略整个占位符段,否则例如模板「遗留」段会把回显后续内容吞进结果」。后续 `coordination-task-lifecycle` 又为其补充了段落长度上限。
