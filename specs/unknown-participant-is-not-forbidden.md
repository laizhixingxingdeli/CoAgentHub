# Spec: 身份不存在和无权限,返回同一个光秃秃的 403

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-26

## 现象:一个死 id 刷了整夜 403,没人看得出为什么

后端日志里 `GET /api/participants/01a0291f-.../task-completion-events`
**每 45 秒一次 403**,持续整夜。查下来该 participant **在库里根本不存在**。

同一原因造成第二个症状:协调者派子任务时被 403 拒绝,它在汇报里写
「当前 Codex 身份被判定为纯执行器」—— 其实不是角色不对,是**它用的身份不存在**。
它随后改用 curl 带正确 id 才成功。

**根因是配置陈旧**:Codex 的 MCP 服务以清库重建前的 id 启动 ——
`COAGENTHUB_PARTICIPANT_ID=01a024ad-…`、`COAGENTHUB_GROUP_ID=01a029c4-…`,
两个都已不存在。

## 平台的问题:两种情况给同一个答案

未知 participant 现在返回:

```json
{"code":"FORBIDDEN","message":"Forbidden"}
```

「你无权」与「这个 id 不存在」是**处置完全相反**的两件事:
前者要检查角色分工,后者要重新绑定身份。而错误信息不给任何线索,
于是调用方只会一遍遍重试同一个死 id ——**这正是它刷了一整夜的原因**。

## 决策

### R1. 身份不存在时,错误要说清

participant 路由(`routes/participant/*`)在 `X-Participant-Id` 或路径中的
participant 在库中**不存在**时,返回**404** 而非 403,消息点明:

> 参与方 <id> 不存在(可能是数据库重建前的旧 id)。请重新注册参与方并更新
> COAGENTHUB_PARTICIPANT_ID。

⚠️ **存在但无权**(如 id 与调用者不符)**仍返回 403,措辞逐字不变**(回归,必测)。
本票只区分「不存在」,不放宽任何权限。

### R2. 群消息路由同样区分

`POST /:id/messages` 中「sender 不是群成员」的裸 403,在 **sender 本身不存在**时
同样返回 404 并点明是身份问题;**是成员表里没有**(participant 存在但未入群)
仍返回 403,措辞点明「不是本群成员」。

⚠️ 现有针对 human / 角色门槛的 403 措辞**逐字不变**(回归,必测)。

### R3. 重复失败要能被看见

同一个不存在的 participant 在 **10 分钟内失败超过 20 次**时,
后端日志输出**一条** warn(不是每次都输出),点明该 id 与建议动作。

⚠️ 只打日志,**不做**封禁、不做限流 —— 局域网内自用,封禁的代价大于收益。
⚠️ 必须去重,否则本票只会把刷屏换个花样。

### R4. 不改这些

- **不改**任何权限判定 —— 本票只改**错误的表达**,不改**谁能做什么**
- **不改** `middleware/participant-identity.ts` 的宽容回落(缺失/非法 id
  回落 Local User 的行为保持)
- **不做**自动重新绑定、不做 id 迁移

## 验收标准

- [ ] 不存在的 participant 请求 participant 路由 → **404**,消息含该 id 与
      「重新注册并更新 COAGENTHUB_PARTICIPANT_ID」
- [ ] 存在但 id 与调用者不符 → **仍 403,措辞逐字不变**(回归,必测)
- [ ] 发消息时 sender 不存在 → 404 并点明身份问题
- [ ] 发消息时 sender 存在但非本群成员 → 403,点明「不是本群成员」
- [ ] human 只读、角色门槛的现有 403 措辞**逐字不变**(回归,必测)
- [ ] 同一死 id 10 分钟内 20 次以上失败 → 日志**只出一条** warn(去重,必测)
- [ ] 未超阈值时**不**输出该 warn
- [ ] `participant-identity` 中间件的回落行为未改动(回归,必测)
- [ ] 后端测试全绿,贴出用例数

## 不涉及

- 权限判定本身(R4)
- 自动重绑定 / id 迁移(R4)
- MCP 服务的配置修复(那是操作动作,由检视者处理)
