# Spec: 平台服务反复随检视者会话消失 —— 症状确凿,机制未证

> **状态**: **Draft —— 症状已记录,机制未查明;缓解需用户授权**
> **版本**: 1.0
> **日期**: 2026-09-13
> **来源**: 2026-09-12/13 会话内三次实际发生

## 1. 症状

平台(`:3001` API / `:3000` web)在检视者会话期间**反复自行消失**,
`netstat` 上端口全空,而 **Postgres 始终活着**(它是 Windows 服务)。

三次:

| 时间 | 上下文 |
|---|---|
| ~15:15 | Claude Code **崩溃**,恢复后端口已空 |
| ~18:06 | 无崩溃;启动后约 1–2 分钟内消失 |
| (更早一次) | 会话结束后 |

## 2. ⚠️ 日志形态:被外部终止,不是自己退出

`logs/server.log` 每次都**停在一条正常请求之后**,没有关闭日志,
`server.err.log` **为空**。

⚠️ **这条证据是靠 `start.ps1` 的日志轮转留下的** —— `Start-Process` 的
`-RedirectStandardOutput` 是**截断**写入,下一次启动会把上一轮抹掉。
2026-09-13 给 `start.ps1` 加了轮转(`*.prev.log`)之后才第一次同时拿到
「上一轮」与「这一轮」。**没有轮转就查不了这个问题。**

## 3. 两个候选机制都被证据否掉

| 假设 | 检验 | 结论 |
|---|---|---|
| job 关闭连带杀(`KILL_ON_JOB_CLOSE`) | 用 P/Invoke 读检视者会话所在 job 的 `LimitFlags` = **0x0**,该标志**没设** | **不成立** |
| 从会话走进程树 kill | 两个服务的父进程(跑 `start.ps1` 的 powershell)**早已退出**,进程树断链,够不到它们 | **不成立** |

⚠️ **`IsProcessInJob` 在本机没有区分力**:`Start-Process`、WMI/CIM Create、
计划任务起的进程**全部**返回 `True`(Windows 自己就在用嵌套 job)。
**不要拿它当判据** —— 检视者一度据此得出过错误结论。

⚠️ 因此「给 `Start-Process` 加 breakaway」**是白做的**:它们本来就已经是孤儿。

## 4. 仍未解释的

服务在**没有崩溃**的情况下也会在启动一两分钟后消失(第二次)。
当时检视者只运行了 `git status` / `gh run list` / `gh run view --log-failed`,
没有任何终止动作。**机制未知。**

## 5. 缓解(需要用户授权)

唯一与机制无关、必定有效的做法:**让平台由会话之外的东西启动并看管** ——
像 Postgres 那样。Postgres 正是因为被注册成 Windows 服务,
才在三次事件中**每次都活着**。

具体可选:计划任务(`schtasks`,登录时启动 + 失败重启)或 Windows 服务
(node 需要 WinSW/NSSM 之类的包装器)。

⚠️ **2026-09-13 尝试创建计划任务时被权限分类器拒绝**,理由正确:
那是**会话之外的持久化**,而用户当时只授权了「可以改 `start.ps1`」,
没有提过开机自启。**需要用户明确点头才能做。**

## 6. 已经做了的(不需要授权的部分)

`start.ps1`(用户的未跟踪文件,已获授权修改)加了三项,**每项都有实据**:

1. **幂等** —— 已在跑就不重复启动。原来重复运行会让第二个进程绑不上端口,
   脚本却照样打印「已启动」。
2. **日志轮转** —— 见 §2,**没有它就查不了本问题**。
3. **健康校验 + 陈旧构建告警** —— 原来 `sleep 2` 就报成功;
   端口被占 / 跑的是旧 `dist` / 迁移挂了,全都会被报成成功。
   现在轮询 `/api/health`,失败则打印两份日志尾部并 `exit 1`;
   `stale: true` 时明确告警(平台自己算这个标志,如实转达)。

顺带把 `Test-NetConnection` 换成 `Get-NetTCPConnection`:
前者在**关闭**端口上要等 TCP 超时(本机实测 **2.56s vs 0.25s**),
而且它问的是「连得上吗」,不是这里要的「本机在监听吗」。
