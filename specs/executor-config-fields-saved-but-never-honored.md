# Spec: 执行器配置里有存了不生效的字段,保存成功暗示了不存在的能力

> **状态**: Frozen
> **版本**: 1.0
> **日期**: 2026-09-08
> **来源**: `docs/implementation-optimization-review-2026-09-07.md` §4 **R8**
> **⚠️ 硬约束**:[executor-adapter-registry.md](executor-adapter-registry.md)
> (Frozen 2026-09-02,ADR-0008)已决定**先做代码适配器注册表,画像暂缓**。
> **不得未经决策重新实现另一套画像引擎。** 本票只解决「说到做到」,
> 不推进适配方案本身。

## 1. 背景与目标

### 1.1 现状证据(检视者已复核代码)

`packages/backend/server/src/lib/executors.ts` 与执行器 API 保存这些字段:

| 字段 | 行 | 实际是否生效 |
|---|---|---|
| `inputMode`(`"path" \| "inline" \| "at-file" \| "stdin"`) | 80, 284, 311 | **部分不生效** |
| `env` | — | **不生效** |
| `outputProfile` | 84, 288, 313 | **只存不读**(已知的分期背景) |

关键证据:

- `packages/backend/server/src/lib/executor-runner.ts:157`
  —— `stdio: ["ignore", "pipe", "pipe"]`,**stdin 是 ignore**。
  所以 `inputMode: "stdin"` 可以保存成功,但**永远不会真的从 stdin 送东西**。
- `queue.ts` 的 CLI 调用主要依赖 **args 占位符**,**没有把 `ex.env` 传给 runner**。
  (`executor-runner.ts:296` 的 `extraEnv` 是 `gitExec` 用的,与执行器配置无关。)

### 1.2 危害

**API 保存成功,给了使用者「配置生效了」的信号,而实际什么也没发生。**

配 `inputMode: "stdin"` 的人会以为任务书走 stdin,配 `env` 的人会以为
子进程拿到了那些变量 —— 两者都不会发生,**而且没有任何提示**。

这与 `outputProfile` 的情况不同:后者的「只存不读」是**有记录的分期决策**
(ADR-0008 批 1),前者是**没人说过的沉默失效**。

### 1.3 目标

**明确区分「支持」「保留(分期)」「未实现」三类字段,
并让未实现的能力不再以保存成功暗示执行生效。**

⚠️ 目标**不是**「把所有字段都实现了」。
把 `inputMode: "stdin"` 真的实现出来是可选的;
**最低要求是不再骗人**。

## 2. 改动范围

| 文件 | 改什么 |
|---|---|
| `packages/backend/server/src/lib/executors.ts` | 字段分类;未支持取值的响应 |
| `packages/backend/server/src/routes/executor/index.ts` | 保存时的响应或能力说明 |
| `packages/backend/server/src/lib/executor-task/queue.ts` / `executor-runner.ts` | **仅在你决定实现 `env` 消费入口时** |
| 文档 | 字段能力表 |
| 对应测试 | 新增用例 |

**不改**:`outputProfile` 的分期状态(它是**有决策**的保留字段,
按「保留」如实标注即可);适配器注册表方案本身;
args 占位符机制;`executor-adapter-registry.md` 的任何决定。

## 3. 详细改动

### R1. 三类字段必须明确,且只有一处出处

给出一张表:每个字段属于**支持 / 保留(分期) / 未实现**。

这张表要有**单一出处** —— 代码里的一处定义,文档从它生成或引用它。
**不要在代码注释、API 文档、README 三处各写一份**,那必然漂移
(这正是 ADR-0008 要治的病)。

### R2. 未支持的取值要有明确响应

保存 `inputMode: "stdin"`(在它未实现期间)时,**不能静默成功**。

处置自选(拒绝保存 + 明确错误 / 接受但在响应里带能力说明),
但**必须让调用方知道这个取值不会生效**。在汇报里说明你选了哪种、为什么。

⚠️ 若选「拒绝保存」,注意**已经存在**的库里可能有这类配置 ——
说明你怎么处理存量(合理答案是「不追溯,只管新写入」,但要明说)。

### R3. `env` 与 `inputMode` 建立单一消费入口

R8 原文要求「为 inputMode 和 env 建立**单一消费入口**」。

即使某个能力暂不实现,**入口要存在且唯一** ——
将来实现时只改那一处,不会又散落到 queue / runner / adapter 三处。

若你决定顺带把 `env` 真的接上:

- 它必须走这个单一入口;
- ⚠️ **注意与 `callback-agent-env-allowlist-and-lease.md` 的取向一致** ——
  那张票的决策是**显式白名单、不继承**。
  server 侧 spawn 执行器的环境策略若与之不同,**要说明为什么不同**,
  不要两边各行其是。

### R4. 不重新实现画像引擎

**硬约束(§0)。** 若你在实现中觉得「用画像更好」,
**停下来报告**,不要动手 —— 那需要推翻 ADR-0008 的分期决策。

## 4. 验收标准

**基线先用工具取**(受影响文件清单自行判断并写进汇报):

```
node scripts/test-baseline.mjs packages/backend/server test/executor-api.test.ts <其它...>
```

1. **核心:端到端验证,不能只检查数据库字段**(R8 原文明确要求)。
   从 **API 保存配置** → 经**真实 runner** → 到**隔离的假执行器**,
   读取假执行器实际收到的 **参数 / stdin / 指定环境变量**。
   ⚠️ **断言 DB 里字段存对了不算通过** —— 那正是当前缺陷能骗过的检查。
   假执行器请用 `test/fake-executor-bin.ts` 的 `resolveFakeExecutor`
   (Windows 上直接 spawn `.sh` 会失败)。
2. **未支持取值有明确响应或能力说明**(R2):给出实际的响应内容。
3. **三类字段表存在且单一出处**(R1):指出它在代码里的位置,
   并说明文档如何引用它而不是复制它。
4. **`outputProfile` 仍按「保留」处理**:不因本票被删或被实现。
5. **既有派发行为不变**:args 占位符路径的用例保持原状态(回归)。
6. 定向测试前后对照,失败数不增加。
7. `npx tsc --noEmit -p tsconfig.json` 通过。

## 5. 不涉及的改动

- **不重新实现画像引擎**(R4,硬约束)。
- 不改 `outputProfile` 的分期状态。
- 不改 args 占位符机制、不改适配器注册表方案。
- **不要求把 `inputMode: "stdin"` 实现出来** —— 实现它是可选的,
  说清楚它不生效是必须的。

## 6. 兼容性

- 若选「拒绝保存未支持取值」,**此前能保存成功的配置现在会被拒** ——
  在汇报里明确列出哪些取值受影响。
- 存量配置不追溯(R2),需明说。
- 若接上了 `env`,**行为变更需显著写明**:此前配了 `env` 不生效,
  现在生效 —— 依赖「配了也没用」的既有配置可能改变行为。
