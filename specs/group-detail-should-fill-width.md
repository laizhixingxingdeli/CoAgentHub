# Spec: 群组详情在宽屏上卡在 1440px,两侧空出大片

> **状态**: Landed — L3 通过(2026-08-26),实现 `9a2e9a62`
> **版本**: 1.0
> **日期**: 2026-08-26

## 现象

群组详情页(`/groups/:id`)在宽屏显示器上不铺满,两侧留出大片空白。

实测(浏览器视口 2560×1440):

| 层级 | 宽度 |
|---|---|
| `main` | 2281px(已铺满) |
| 内层容器 | **1440px** ← 卡在这里 |
| 空出的左右留白 | 合计约 840px |

`main` 本身是铺满的,收窄发生在它内部:

```
packages/frontend/web/src/pages/app/groups/messages/index.tsx:68
<div className="mx-auto flex h-[calc(100dvh-4rem)] w-full max-w-[1440px] flex-col px-4 sm:px-6">
                                                  ^^^^^^^^^^^^^^^
```

**1440px 及以下的屏幕看不出问题**,因为主区实际宽度(1440 视口下为 1161px)
还没顶到这个帽子。它只在更宽的显示器上暴露 —— 这也是它一直没被发现的原因。

## 决策

### R1. 去掉群组详情的宽度帽子

移除 `pages/app/groups/messages/index.tsx:68` 的 `max-w-[1440px]`,
让该容器随 `main` 铺满。`mx-auto` 随之失去意义,一并移除;
`w-full`、`px-4 sm:px-6`、高度与 flex 方向**保持不变**。

### R2. 只改这一处

⚠️ 同样的 `max-w-[1440px]` 还出现在另外四处:

- `pages/app/groups/index.tsx:93`(群组列表)
- `pages/app/groups/members.tsx:505`(成员管理)
- `pages/app/help/index.tsx:49`
- `pages/app/feedback/index.tsx:13`

**本票一处都不动。** 列表、帮助、反馈是以阅读为主的页面,过宽的行长反而伤可读性;
群组详情是并排工作区(消息 + 上下文面板),宽度越大越有用 —— 两类页面的诉求相反。
要不要改其它页面是**单独的产品决定**,不在本票范围。

### R3. 不引入新的宽度约束

不要用 `max-w-screen-2xl`、`container` 等换一顶更大的帽子替代;
本票要的是**不设上限**。若后续发现超宽屏下行长过长,那是另一个问题,另立票。

### R4. 不动布局结构

不改 flex 方向、不改高度算式 `h-[calc(100dvh-4rem)]`、不动内部子组件的
`flex-1` / `min-w-0`。本票只删一个宽度上限。

## 验收标准

- [ ] 2560px 宽视口下,群组详情的内层容器宽度 **等于** `main` 的宽度(不再是 1440)
- [ ] 1440px 及以下视口下,布局与改动前**逐像素一致**(回归,必测)
- [ ] 群组列表 / 成员管理 / 帮助 / 反馈四页的 `max-w-[1440px]` **仍在**(回归,必测)
- [ ] 消息区与上下文面板的横向比例关系不变(仍由各自的 flex 规则决定)
- [ ] 无横向滚动条(`document.documentElement.scrollWidth` 不超过视口宽度)
- [ ] 前端测试全绿,贴出用例数

## 不涉及

- 其它四个页面的宽度(R2)
- 超宽屏下的行长优化(R3)
- 布局结构与内部比例(R4)
