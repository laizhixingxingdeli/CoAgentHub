# Spec: 标 `failed` 就能绕开 L1 守卫,而代码照样落地

> **状态**: Landed — L3 通过(2026-08-26),实现 `c4529cda`
> **版本**: 1.0
> **日期**: 2026-08-25
> **补齐**: `escape-hatch-became-the-default`(`e824be15`)的 **R4「只管 done」**

## 现象

`escape-hatch-became-the-default` 的守卫落地后,协调者**第三次**自己实现
(提交 `d58ba392`,零执行子任务)。这次它没有伪装 `done`,而是标了 `failed`:

> 实现已完成并提交 d58ba392,但当前 task 被群成员角色判定为协调任务
> 且没有执行子任务;按 R1 规则拒绝将该直接实现伪装为 done。

**诚实,但守卫没起作用** —— R4 明确写了「只管 done,不管 failed/cancelled」。
于是:代码落地了、测试绿了、L1 仍然没发生,而任务记录是 `failed`。

## 这不是要把守卫扩到 failed

⚠️ **不要**把 R1 的拒绝扩到 `failed`。协调者已经把代码提交了,
如果连 `failed` 也拒绝,它将**无法关闭这个任务**,链路彻底卡死 ——
比现状更糟。

真正缺的不是更多阻拦,是**这件事发生过要留下痕迹、能被统计**。
现在它只存在于一句人写的 `error` 文本里,**查不出来、数不出来**。

## 决策:不拦,但记录成结构化事实

### R1. 终态关闭时一律检测,结果写进 `diffSummary`

协调任务落**任一终态**(`done` / `failed` / `cancelled`)且**零执行子任务**时,
执行与 R1 守卫相同的窗口提交检测,并由**平台写入** `diffSummary.l1Bypass`:

```json
{"l1Bypass": {"commits": ["<hash>", "..."], "windowStartedAt": "<iso>"}}
```

- 窗口内**无**提交 → **不写该字段**(不要写 `null`,不要写空对象)
- git 不可用 → **不写该字段**(与 R2 放行口径一致)

平台写入 `diffSummary` **已有先例**:`claimVerification` 就是这样落的
(`executor-task/queue.ts`),沿用同一模式,不新建表、不加列。

### R2. `done` 仍然拒绝,行为不变

`done` 分支的 400 拒绝**逐字不变**(回归,必测)。本票只覆盖
`failed` / `cancelled` 这两条此前完全不检测的路径。

### R3. 有执行子任务时不检测

零子任务才是本票的场景。有执行子任务 → **完全不做检测、不写字段**
(回归,必测)。L1 发生过就没有绕开可言。

### R4. 任务详情透出该字段

`GET /groups/:id/tasks/:taskId` 的响应中透出 `l1Bypass`(无则不出现),
使其**可查询、可统计**。

⚠️ **不做**前端展示 —— 那是另一张票的事,本票只到 API 为止。

### R5. 不改这些

- **不改** `done` 分支的拒绝逻辑与错误文案(R2)
- **不改**窗口口径 —— 仍复用 `attempts[0].startedAt`
- **不改** `commitsInTaskWindow` 的实现(直接复用)
- **不做**自动补下发、不做任何阻拦

## 验收标准

- [ ] 零子任务 + 窗口内有提交 + `failed` → **200**,`diffSummary.l1Bypass`
      含提交哈希与窗口起点
- [ ] 同上但 `cancelled` → 200,同样写入
- [ ] 零子任务 + 窗口内**无**提交 + `failed` → 200,**不写** `l1Bypass` 字段
- [ ] git 不可用 → 200,**不写**该字段,不抛错
- [ ] **有**执行子任务 + `failed` → 200,不检测、不写字段(回归,必测)
- [ ] `done` 分支的 400 拒绝行为**逐字不变**(回归,必测)
- [ ] 任务详情响应透出 `l1Bypass`;无该字段的任务响应中不出现该键
- [ ] 平台写入不覆盖执行器自报的其它 `diffSummary` 字段(回归,必测)
- [ ] 后端测试全绿,贴出用例数

## 不涉及

- 前端展示(R4)
- `done` 分支(R2)
- 把守卫扩到 failed(明确不做,理由见上)
