# Spec: 时间线分层按消息形态而非动作主体,下发落错了层

> **状态**: Landed — L3 通过(2026-08-26),实现 `813077e7`
> **版本**: 1.0
> **日期**: 2026-08-25
> **修正**: `requirement-detail-layer-grouping`(`a95daf4c`)的 **R2 归属规则**

## 现象

用户指出:详情页的 L1–L3 分段里,**检视者下发应当在 L3**,其余以此类推。核查属实。

`merge-requirement-timeline.ts` 的 `timelineLayerForEvent` 末行是:

```ts
return "l1";     // 所有不是已知结构化载荷的消息,一律归 L1
```

而**下发的任务书是自由文本 markdown,不是结构化载荷** —— 于是:

| 记录 | 当前归属 | 应归 |
|---|---|---|
| **检视者下发的任务书** | **L1** ❌ | **L3** |
| 检视者的 `review_result` | L3 ✓ | L3 |
| 协调者的 `review_request` | L2 ✓ | L2 |
| **协调者派发给执行器的任务书** | **L1** ❌ | **L2** |
| 执行任务卡片 / 输出 / 控制 | L1 ✓ | L1 |

后果:**L3 段只有裁决、没有下发** —— 看不出这条需求是谁、何时、依据哪份 spec
发起的;而 L1 段混进了两级的任务书。

## 根因:我写的 R2 规则本身是错的

`requirement-detail-layer-grouping` R2 写着:

> | 任务书、群内对话等自由文本 | **L1**(执行与沟通记录,沿用现名) |

**这条按「消息形态」分层,而层的语义是「谁做的动作」。** 形态(结构化载荷 vs
自由文本)与动作主体无关 —— 检视者既发结构化的 `review_result`,也发自由文本的
任务书,两者都是**检视者的动作**,理应同层。

## 决策:改按动作主体分层

### R1. 分层判据改为「谁做的」

```
L3 ← 检视者的动作:下发任务书、spec_published / spec_amended、review_result
L2 ← 协调者的动作:派发给执行器的任务书、review_request、L2 结论
L1 ← 执行器的动作:执行任务卡片、执行输出、汇报、停止/回滚控制
```

**判据用发送者在本群的角色**,不是消息形态:

- 消息事件 → 查 `senderId` 在本群 `group_members.roles`
  - 含 `reviewer` → **L3**
  - 含 `coordinator` → **L2**
  - 含 `executor` → **L1**
  - `human` → **L3**(外部触发方与检视者同层,都是「发起侧」)
- 任务事件 → 沿用现有规则(执行子任务 → L1,协调任务 → L2)

### R2. 结构化载荷的归属由「主体」决定,不再单独判形态

现有对 `review_result` / `spec_*` / `review_request` 的特判**可以保留作为兜底**
(发送者角色查不到时使用),但**主判据是角色**。

理由:同一种载荷可能由不同角色发出(如两方编制下协调者兼任检视者职责,
它发的 `spec_published` 属于它当时承担的哪一层,由角色决定更准)。

### R3. 角色查不到时的兜底

发送者不在群成员表中(已退群、历史数据)→ **回落到现有的形态判据**;
形态也无法判定 → **归 L1** 并保持现状,**不丢弃记录**。

### R4. L1 段改名

现名「L1 执行与沟通记录」中的「沟通记录」是上一版把自由文本塞进 L1 的产物。
改动后 L1 只含执行器动作,**改为「L1 执行」**。

⚠️ 若某处 `data-testid` 依赖旧名,**testid 不变**,只改显示文案。

### R5. 不改这些

- **不改**三段式布局结构与折叠行为
- **不改**层状态判定(`requirement-layer-state.ts` 的 `deriveL1/L2/L3`)——
  那是「每层做到哪一步」,与「哪条记录属于哪层」是两件事
- **不改**后端

## 验收标准

- [ ] 检视者下发的任务书出现在 **L3 段**,不再在 L1
- [ ] 协调者派发给执行器的任务书出现在 **L2 段**
- [ ] `review_result` / `spec_published` / `spec_amended` 仍在 L3(回归)
- [ ] `review_request` 仍在 L2(回归)
- [ ] 执行任务卡片、输出、停止/回滚仍在 L1(回归,必测)
- [ ] `human` 触发的下发归 **L3**
- [ ] 发送者不在成员表时回落形态判据,**记录不丢失**
- [ ] L1 段标题显示为「L1 执行」,`data-testid` **未改名**
- [ ] 层状态判定(`deriveL1/L2/L3`)**未被改动**(回归,必测)
- [ ] 前端测试全绿,贴出用例数
- [ ] **未改动**后端

## 不涉及

- 层状态判定(R5)
- 后端
