# Spec: 把剩余测试文件迁移到跨平台假执行器助手

> **状态**: Frozen
> **版本**: 1.0
> **日期**: 2026-09-08
> **前置**: [windows-test-baseline-fake-executor.md](windows-test-baseline-fake-executor.md)
> (Landed,`ed7e2428`)已建立助手 `test/fake-executor-bin.ts` 并迁移 3 个样板文件,
> 实测 **39 红 → 9 红、耗时减半**。本票把同一手法铺到剩余文件。

## 1. 背景与目标

### 1.1 现状

| 观测 | 数字 |
|---|---|
| 后端红基线(迁移前) | **129 failed / 924 passed**(2026-09-07) |
| 仍在用 `#!/bin/sh` 假执行器的测试文件 | **21 个**(总 24,已迁 3) |
| 已迁移的 3 个 | `retry-rollback-guard` / `executor-task-repo` / `executor-queue`:39 红 → 9 红 |

红基线的**绝大部分**来自这 21 个文件:Windows 无法直接 spawn `.sh`,
依赖执行器生命周期的用例统统超时。

### 1.2 危害(为什么值得做)

红基线不是「慢」,是**没有信号**:每张票的验收都退化成「在红海里数增量」,
真回归可能被淹没。检视者今晚每一张票都必须手工做前后对照才敢下结论。

**这张票的收益不在自己,在它之后的每一张票。**

### 1.3 目标

剩余 21 个文件全部改用助手,**不改任何 `#!/bin/sh` 脚本内容、不改任何断言意图、
不改生产代码**。

## 2. 改动范围

| 范围 | 内容 |
|---|---|
| 改 | `packages/backend/server/test/` 下仍在用 `#!/bin/sh` 的 21 个测试文件 |
| 不改 | `test/fake-executor-bin.ts`(助手已定型,除非发现真缺陷);任何 `.sh` 脚本正文;`packages/backend/server/src/**`;`vitest.config.ts`;CI;依赖 |

**这 21 个文件不得在一张任务书里一次改完。** 见 §3 R1。

## 3. 详细改动

### R1. 分批,每批一张任务书、一个提交边界

由协调者按**文件相关性 + 单批可验收**拆批,建议每批 3–5 个文件。
理由(报告 §11.3 P2 与今日实证):一张票塞太多,中途被打断时留下的半成品
最难收拾;而拆太碎又会引入多次 CLI 启动与上下文读取的固定开销。

**每批必须能独立取基线、独立验收、独立提交。**

### R2. 迁移手法(照抄样板,不要发明)

参照已迁移的三个文件:

1. `import { resolveFakeExecutor } from "./fake-executor-bin"`(路径按文件位置调整);
2. 把「直接用脚本路径当 `bin`」改成用助手返回的 `bin` + `argsPrefix`;
3. **`argsPrefix` 拼在原有 args 最前面**,原有 `{ticket}` 等占位参数**顺序不变**;
4. 若该文件通过 `POST /api/executors` 播种执行器配置,`bin`/`args` 同样改用助手结果。

### R3. 不碰断言

**只改「假执行器怎么被启动」,不改任何断言与测试意图。**
若某条用例在修好 spawn 之后仍然红,按 R4 分类,**不得**改断言让它变绿。

### R4. 每批必须给出残留红的分类

对每条仍然红的用例分类:
① 假执行器 spawn 问题(本票应已消除)② 其它 Windows 平台问题
(已知两类:**win32 进程树终止**、**`/tmp` 语义分裂**,各自另票)③ **真实缺陷**。

**判不出就写「未能判定」并说明查过什么。不得为了数字好看跳过或改写用例。**

发现 ③ 时**必须显式列出来** —— 那是这张票最有价值的产出。

## 4. 验收标准

### 4.1 每批

1. **基线对照**:用 `node scripts/test-baseline.mjs packages/backend/server <本批文件...>`
   取改前改后两行,贴进汇报。**失败数必须下降**(本票的目的就是降它);
   若某批下降为 0,说明该批的红另有原因,按 R4 分类说明。
2. **残留红逐条分类**(R4)。
3. **零生产代码改动**:`git show --stat` 不得出现 `packages/backend/server/src/**`。**硬约束。**
4. **未改 `.sh` 脚本正文**:`git show` 里不得出现 `#!/bin/sh` 脚本内容的增删
   (助手调用处的改动除外)。
5. `npx tsc --noEmit -p tsconfig.json` 通过。

### 4.2 全票收口(全部批次完成后)

6. **全量后端回归**取一次,与迁移前基线 **129 failed / 924 passed** 对照,
   贴出实际数字。⚠️ 这一跑约 **24 分钟**,**只在全部批次完成后跑一次**,
   不要每批都跑。
7. 仍在用 `#!/bin/sh` 且未迁移的文件数为 **0**:
   ```
   grep -rl '#!/bin/sh\|#!/usr/bin/env bash' packages/backend/server/test/ | wc -l
   ```
   期望输出 `0`(助手文件本身不含该串)。若有文件确实不适合迁移,
   **列出来并说明原因**,不要静默跳过。

## 5. 不涉及的改动

- **不修 win32 进程树终止**(另票)。
- **不修 `/tmp` 语义分裂**(另票)。
- **不改生产代码**、不改 `vitest.config.ts` / CI / 依赖。
- **不改助手本体**,除非发现它有真缺陷 —— 那时停下来报告,不要顺手改。
- 不为提速跳过或删除用例。

## 6. 兼容性

- 非 win32:助手第一分支原样返回,行为逐字不变。
- 无生产代码改动,无 schema 变更。
