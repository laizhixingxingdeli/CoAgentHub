# Spec: 协调任务在子任务还在跑的时候就结案了

> **状态**: Landed — L3 通过(2026-08-26),实现 `84605aba + 6c72d83f(夹具修正)`
> **版本**: 1.0
> **日期**: 2026-08-25
> **补齐**: `coordination-close-integrity` R1

## 现象

协调任务 `01a03965` 落 `done` 时,其子任务 `01a03970` **仍处于 `running`**:

```
01a03965 | done    | ROOT
01a03970 | running | parent=01a03965
```

## 为什么这是问题

L2 功能检视的定义是「**任务终态后**逐条对照 spec 验收标准」。
子任务还在跑就结案,意味着 L2 是**对着一个未完成的执行**做的 ——
后续输出、失败、重试都不再被任何人看见。

平台已经有 `l1.allTerminal` 这个派生字段,**恰好表达这件事**,
但结案路径没有读它。

## 决策

### R1. `done` 结案要求全部子任务已终态

协调任务落 `done` 且**存在**执行子任务时,要求全部子任务处于终态
(`done` / `failed` / `cancelled`)。存在非终态子任务 → **400**,
错误须列出**非终态子任务的 id 与当前状态**。

判据**复用现有 `l1.allTerminal` 的派生逻辑**(`lib/l1-aggregate.ts`),
**不另写一套终态集合** —— 两处各写一套必然分叉。

### R2. 零子任务时不触发

零子任务走的是现有逃生舱路径,与本票无关(回归,必测)。

### R3. `failed` / `cancelled` 不触发

与 `coordination-close-integrity` R3 一致:协调者要能在异常情况下关闭任务,
否则链路卡死。

### R4. 不改这些

- **不改** `l1-aggregate.ts` 的派生逻辑(只读用,不改)
- **不改**零子任务分支与提交检测
- **不做**自动等待/轮询 —— 平台不替协调者等,只拒绝这次结案;
  协调者稍后重试即可

## 验收标准

- [ ] 有非终态子任务 + `done` → **400**,错误含该子任务 id 与状态
- [ ] 全部子任务终态 + `done` → 200(回归,必测)
- [ ] 零子任务 + `done` → 走现有逃生舱路径,行为不变(回归,必测)
- [ ] 有非终态子任务 + `failed` → 200(不触发,回归)
- [ ] 多个子任务其一非终态 → 400,**只列出非终态的那个**
- [ ] 终态集合与 `l1.allTerminal` 一致(读代码确认复用,不另写)
- [ ] 后端测试全绿,贴出用例数

## 不涉及

- 提交归属(见 `commits-must-belong-to-an-execution-child`)
- `failed` / `cancelled` 分支
- 自动等待(R4,明确不做)
