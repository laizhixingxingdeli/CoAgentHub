# Spec: 这一轮补的可观测字段,人一个都看不见

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-24
> **前置**: `requirement-detail-layer-grouping`(`a95daf4c`)—— 三段式布局已就位,
>   本票把字段落进去

## 背景:我把「可观测」做成了只对 agent 可观测

这一轮为了消除各种盲区,新增了 5 个 API 字段:

| 字段 | 回答什么问题 | 前端引用数 |
|---|---|---|
| `l1.childCount` / `supersededCount` | L1 到底发生了没有?换过几次执行器? | **0** |
| `l3.answered` / `overdue` | 交回 L3 之后有人应答吗?等多久了? | **0** |
| `runtime.stale` | 我现在看到的接口,包含刚落地的改动吗? | **0** |
| `liveness.warning` | 这个执行器是不是已经静默死了? | **0** |

**全部为 0。界面上什么都没变。**

这很讽刺:**这一整轮是用户看着界面问「没有一个走完三层的吗」才开始的。**
我把每个盲区都补成了 API 字段,而最初提出问题的是人 —— 下一次出问题,
他看到的仍然是和当初一样的画面。

## 关键判断:三种字段的语义层级不同,不能一律塞进需求详情

| 字段 | 语义层级 | 归属 |
|---|---|---|
| `l1` / `l3` | **单条需求**的检视链状态 | 需求详情的对应层段 |
| `liveness` | **单个执行任务**是否静默 | L1 段里那张任务卡片 |
| `runtime.stale` | **整个后端进程**是否陈旧 | **全局**,不属于任何一条需求 |

⚠️ **`runtime.stale` 不得在每条需求详情里渲染** —— 它对所有需求都是同一个值,
逐条显示纯属噪音。它要出现在**一个全局位置**。

## 要求

### R1. L1 段标题行:执行次数与替代次数

L1 段标题行的摘要(现已显示「2 次执行」)补充替代信息:

- `supersededCount > 0` → 「N 次执行 · 换过 M 次执行器」
- `supersededCount === 0` → 保持现状「N 次执行」

`childCount === 0` 且 L1 为 `na-declared` 时,沿用已有的「不适用 · 已声明理由」,
**不叠加执行次数**。

### R2. L3 段:未答复与超时可见

`l3` 字段存在时,在 L3 段标题行体现:

| 状态 | 显示 |
|---|---|
| `answered: true` | 沿用现有裁决展示,**不变** |
| `answered: false`, `overdue: false` | 「等待检视 · 已等待 N 分钟」(中性色) |
| `answered: false`, `overdue: true` | 「**等待检视超时** · 已等待 N 小时」(**警示色**) |

等待时长由 `awaitingSince` 算出。这是**本轮 16 次误判的根源** ——
此前「交出去没人应答」与「检视者正在认真看」在界面上完全无法区分。

### R3. L1 段的任务卡片:静默告警

执行任务的 `liveness.warning === true` 时,在该任务卡片上显示
「**疑似中断** · 已 N 分钟无信号」(警示色)。

`liveness` 为 `null` 或 `warning: false` → **不显示任何东西**,不占位。

### R4. `runtime.stale` 放全局,且要克制

后端陈旧时,在**页面级**显示一条提示(建议顶部细横幅或状态区),内容说明:

> 后端运行的不是最新构建 —— 你看到的接口可能不含刚落地的改动

- **只在 `stale: true` 时出现**,正常时**完全不占空间**
- **全局只出现一次**,不随需求切换重复
- **可关闭**(本次会话内不再提示),但下次 `stale` 重新变 true 时再出现
- 数据源用 `GET /api/health`(全局端点),**不要**从某条任务的 `runtime` 字段取 ——
  那是同一份信息挂在任务上的副本,拿它当全局状态是借道

⚠️ **不要做成阻断式弹窗或红色警报。** 陈旧不等于错误(`stale-runtime-detection`
R4 已定「只报不拦」),UI 也应保持同一立场:**告知,不打断**。

### R5. 一律不新增后端改动

5 个字段**都已在 API 中就位**,本票纯前端消费。

### R6. 不改这些

- **不改**三段式布局结构(`requirement-detail-layer-grouping` 刚落地)
- **不改**现有 `data-testid`
- **不改**任何后端文件

## 验收标准

- [ ] `supersededCount > 0` 的需求,L1 段显示「N 次执行 · 换过 M 次执行器」
- [ ] `supersededCount === 0` 时显示**与改动前一致**(回归)
- [ ] `na-declared` 的 L1 段**不叠加**执行次数
- [ ] `l3.answered: false` 且未超时 → 显示「等待检视 · 已等待 N 分钟」(中性色)
- [ ] `l3.overdue: true` → 显示「等待检视超时」并用警示色
- [ ] `answered: true` 的展示**与改动前一致**(回归)
- [ ] `liveness.warning: true` 的任务卡片显示「疑似中断 · 已 N 分钟无信号」
- [ ] `liveness` 为 null 或 false → **不占位**,卡片与改动前一致(回归)
- [ ] 后端 `stale: true` 时页面级提示出现;`false` 时**完全不占空间**
- [ ] 该提示**全局只出现一次**,切换需求不重复
- [ ] 该提示可关闭,且**不是**弹窗/阻断式
- [ ] 全局提示的数据源是 `GET /api/health`,**不是**任务的 `runtime` 字段
- [ ] **未改动**后端;未改动三段式结构与现有 testid
- [ ] 前端测试全绿,贴出用例数

## 不涉及

- 后端任何改动(R5)
- 三段式布局(前置票已定)
- 新增任何可观测字段(本票只消费已有的)
