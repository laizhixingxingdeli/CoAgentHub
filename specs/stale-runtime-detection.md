# Spec: 运行中的后端比构建产物旧 —— 唯一还纯靠纪律的环节

> **状态**: Landed — L3 通过(2026-08-24),实现 `0e055cf3`
> **版本**: 1.0
> **日期**: 2026-08-24

## 背景:检视者本轮为此栽了三次

后端以 `node dist/server.mjs` 常驻运行。执行器改完代码 → 重新 `build` → **进程
不会自动换**。于是「代码已改、测试全绿、提交已落」与「运行中的服务包含这些改动」
是**两件事**,而它们看起来一模一样。

本轮实测踩中三次:

| 次数 | 表现 |
|---|---|
| 1 | 后端 23:58 启动,修复 00:13 落地。**十小时里 12 张票全部跑在未修复的后端上**,我以为验证过了 |
| 2 | `skill-sync` 的 digest 端点全部 404 —— 路由在源码里,进程是旧的。我一度以为实现有问题 |
| 3 | 反向:上一张票刚因我抢着重启而误判 `failed`,这次矫枉过正**没重启**,又验错 |

三次都不是执行方的问题,是**「运行的是不是刚合进去的代码」这个判断没有任何机制
支撑**,只能靠人记得。

我已把检查写进记忆,但**记忆只约束我一个** —— 换一个 agent 做 L2/L3 一样会栽,
而且栽了还看不出来:它会得到一个功能"不存在"或"没生效"的结论,然后据此判错。

## 决策:平台自报陈旧,不阻塞

### R1. 服务自测陈旧度

服务启动时记录**自身入口文件的 mtime** 与**进程启动时刻**。之后任何时候:

```
陈旧(stale) ⟺ dist 入口文件当前 mtime > 进程启动时刻
```

含义:**构建产物在本进程启动之后被更新过,运行中的代码不是最新构建的代码。**

- 入口文件路径从 `process.argv[1]` 或 `import.meta.url` 取,**不要硬编码**
  `dist/server.mjs` —— dev 模式(`tsx watch src/index.ts`)下路径不同
- 判定是**一次 `stat` 调用**,不扫描源码树。不做「源码比 dist 新」的检查 ——
  那需要遍历,代价与收益不匹配,且本轮三次事故全是本条能覆盖的情形
- 取不到 mtime(路径异常等)→ **视为不陈旧**,不报错、不阻塞

### R2. 暴露给验收方

新增轻量端点(建议 `GET /api/health`,若已有同类端点则并入):

```json
{
  "startedAt": "2026-08-24T10:20:42.000Z",
  "entryMtime": "2026-08-24T10:19:58.000Z",
  "stale": false
}
```

**不需要鉴权**(LAN 全信模型,与其余读接口一致)。

### R3. 在验收方会看到的地方surface

协调任务详情(`GET /groups/:id/tasks/:taskId`)增加 `runtime` 字段:

```json
"runtime": { "stale": true, "startedAt": "...", "entryMtime": "..." }
```

理由:L2 与 L3 都在这里读任务、据此判断验收结论。**把信号放在他们必然经过的
地方**,而不是指望他们主动去查健康端点 —— 与本轮 `l1` / `l3` 派生字段同一思路。

- 与 `l1` / `l3` 一致:**仅协调任务输出**,非协调任务不含该字段
- 字段为**实时求值**(读详情时 stat 一次),不是启动时的快照 ——
  否则进程启动后产物被更新就永远测不出来

### R4. 只报不拦

**不阻塞任何操作**:不拒绝下发、不拒绝 PATCH、不改变任何状态转移。

理由:陈旧不等于错误 —— 有时就是想在旧版本上跑一次对照。平台的职责是**让它可见**,
判断留给人和 agent。这与 `l3-verdict-observability` 的 R5 同一立场。

### R5. 启动日志提示

服务启动时若入口文件 mtime **晚于**上一次记录的启动(无法得知则跳过),
输出一行日志说明当前入口构建时间。**只输出信息,不判断对错。**

### R6. 不做这些

- **不做**自动重启、自动重建
- **不做**源码树扫描(R1 已说明)
- **不改**任何现有端点的既有字段
- **不改**前端

## 验收标准

- [ ] `GET /api/health` 返回 `startedAt` / `entryMtime` / `stale`
- [ ] 进程启动后**触摸入口文件**(`touch dist/server.mjs`)→ `stale` 变 `true`
      (实测,本票核心)
- [ ] 未触摸时 `stale` 为 `false`
- [ ] 入口路径由 `argv[1]` / `import.meta.url` 推导,**未硬编码** `dist/server.mjs`
- [ ] 取不到 mtime 时视为不陈旧,**不抛错**
- [ ] 协调任务详情含 `runtime` 字段,值与健康端点一致
- [ ] **非**协调任务详情**不含** `runtime` 字段(与 `l1`/`l3` 处理一致,回归必测)
- [ ] `runtime.stale` 是**实时求值** —— 进程启动后触摸文件,再读详情即变 `true`
- [ ] 陈旧时**不阻塞**下发与 PATCH(回归,必测)
- [ ] 未新增自动重启/重建;未扫描源码树
- [ ] 后端测试全绿,贴出用例数

## 不涉及

- 自动重启/热重载
- 「源码比 dist 新」的检测(R1)
- 前端展示 `runtime`(另开票)

## 执行环境提示

- 本仓 pnpm 项目,后端 `:3001`
- **本票落地后要验证它自己**:重启后 `stale` 应为 `false`,
  `touch packages/backend/server/dist/server.mjs` 后应变 `true`
- 改完重启后端;**重启前确认无 running/queued 任务**
