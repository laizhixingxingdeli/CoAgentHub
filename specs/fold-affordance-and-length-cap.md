# Spec: 展开入口太弱,展开后收不回来

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-23

## 背景

任务详情里有三处「长内容折叠」,用的是同一套样式:

```
RequirementTimeline.tsx:256   消息卡片
RequirementTimeline.tsx:441   任务卡片
RequirementDetailPanel.tsx:358 层结论(L2/L3)
```

```tsx
className="mt-1.5 text-xs font-medium text-muted-foreground
           underline-offset-2 transition-colors hover:text-foreground hover:underline"
```

**两个问题:**

**① 入口比正文还弱。** 最小字号 + 灰色 + 无边框纯文字,下划线要 hover 才出现。
正文是 `text-sm`,也就是**「展开」比它要展开的内容更不显眼**。而这是这个界面上
最需要被发现的操作——不点开就看不到执行详情。

**② 展开后没有任何高度上限。** 展开渲染的是全量文本:

```tsx
{foldable && expanded && (
  <div className="mt-1.5 space-y-1.5 border-t pt-1.5">   {/* 无 max-height */}
```

执行器输出动辄上千行。展开一条,页面被顶开老长,滚到底部**没有任何收起入口**——
要收起得一路滚回卡片顶部。

## 要求

### R1. 提高展开入口的视觉权重

三处共用一套,**抽成一个共享组件**(现在是三处各写一遍同样的 className,
本身就是重复)。要求:

- 字号不低于正文(`text-sm`)
- 有稳定可见的边界(按钮态/边框/背景任选其一),**不依赖 hover 才显形**
- 带方向指示(如 chevron),展开态与折叠态不同
- 折叠态提示内容量,让用户判断值不值得展开(例如「展开(约 1.2 万字)」或
  「展开 · 320 行」)。**取现成可得的度量即可**,不要为此做昂贵计算

⚠️ **不要做成主按钮。** 它比现在醒目一档就够,不要抢走任务状态与内容的注意力。

### R2. 展开态设高度上限 + 内部滚动

展开区域设 `max-height`(建议按视口比例,如 `60vh`)+ `overflow-y: auto`。

理由:上限的意义不只是省空间,而是**让「收起」按钮永远留在视口可达范围内**——
内容在自己的容器里滚,页面不被顶开。

### R3. 展开态必须有一个「一直够得着」的收起入口

满足以下**任一**即可,由执行者选:

- 收起按钮吸顶(`sticky top-0`)在展开区内
- 展开区底部再放一个收起入口
- 展开区顶部的入口本身因 R2 的高度上限而始终可见

**验收看行为,不看实现**:展开一条上千行的输出,滚到内容底部,**不滚回去就能收起**。

### R4. 三处行为一致

抽出的共享组件必须被三处都用上。**不允许**只改一处或三处各留一套。

### R5. 现有 `data-testid` 保持不变

`requirement-timeline-toggle-${id}` / `${testId}-toggle` 等定位符沿用,
`aria-expanded` 保留。

## 验收标准

- [ ] 三处折叠入口由**同一个共享组件**渲染
- [ ] 入口字号 ≥ `text-sm`,不 hover 也有明确可见边界
- [ ] 入口带方向指示,展开/折叠态视觉不同
- [ ] 折叠态显示内容量提示
- [ ] 展开区有 `max-height` + 内部滚动,页面不被顶开
- [ ] **展开一条上千行输出,滚到底部,不滚回顶部就能收起**(实测,这是本票核心验收)
- [ ] 现有 `data-testid` 与 `aria-expanded` 未变
- [ ] `prefers-reduced-motion` 下无动画抖动
- [ ] 前端测试全绿,贴出用例数

## 不涉及

- 折叠阈值的具体数值(`FOLD_THRESHOLD = 80`)—— 保持现状,本票不调
- 实时输出终端块(`LiveOutput`)的内部实现
- 消息卡片与任务卡片的其它样式
