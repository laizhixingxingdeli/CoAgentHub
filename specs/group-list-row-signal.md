# Spec: 群列表每行看不出这个群在干什么

> **状态**: Landed — L1/L2/L3 均通过(2026-08-23)
> **版本**: 1.0
> **日期**: 2026-08-23

## 现象(浏览器实测 `/groups`)

每行只有:**群名 + 铅笔图标 + 「3 名成员」+ 相对时间**。

```
DSH 插件 ✏️
3 名成员                                    11小时前
```

看不出:有没有任务在跑、跑到哪了、有没有失败、卡住没有。
「3 名成员」几乎是这个群**最不需要知道**的一件事——成员是配置,不是状态。

群列表是这个平台的首页。**首页应该回答「哪里需要我关注」,现在它只回答「有哪些群」。**

## 另一处:参与方设置卡片放错了位置

列表页顶部有一张可展开的「参与方设置」卡片。它与群列表无关,
而左侧导航已有独立的「接入参与方」入口——同一件事两个入口,且其中一个在不相干的页面里。

---

## 要求

### R1. 每行呈现该群的实时状态

至少要能一眼看出:

- **有没有任务在跑**(running)
- **有没有需要关注的**(failed / 结果未确认 / 无进展提醒)
- 最近一次活动是什么时候(现有的相对时间保留)

数据来源自行判断。可考虑:`GET /groups/:id/tasks` 的状态聚合;
若判定需要后端支持(如让 `GET /groups` 带任务状态计数),
**不要自行改后端**,在汇报里说明理由,由检视者另行立票。

呈现形态自行设计,但:

- **不要堆数字**。「2 running / 5 done / 1 failed」这种是仪表盘不是列表行
- **异常必须比正常显眼**。有 failed 的群要能在一屏里被立刻找到
- 全部完成、无异常的群应当**安静**——不抢注意力

### R2. 「N 名成员」降级或去掉

成员数是配置不是状态,不该占据与状态同等的位置。
去掉、或缩成次要信息(如 hover 显示),自行判断。

### R3. 移除列表页的「参与方设置」卡片

- 该卡片从群列表页移除
- ⚠️ **确认功能不丢失**:若卡片里有「接入参与方」页面没有的能力,
  **在汇报里指出**,不要静默丢掉

### R4. 归档群与活跃群要有视觉区分

当前「全部」tab 下两者混排、外观一致。归档群应当明显更弱(灰度/降低对比),
但仍可读。

## 验收标准

- [ ] 每行能看出该群有无任务在跑、有无异常
- [ ] 有 failed / 未确认任务的群在列表中显眼
- [ ] 无异常的群不抢注意力
- [ ] 未堆砌状态计数
- [ ] 「N 名成员」不再与状态同级
- [ ] 列表页无「参与方设置」卡片;能力丢失情况已在汇报中说明
- [ ] 归档群与活跃群视觉可区分
- [ ] 若判定需改后端,已说明理由且**未擅自改后端**
- [ ] 新增测试覆盖:有 running 的群、有 failed 的群、全完成的群、归档群
- [ ] `pnpm --filter @laizhixingxingdeli/web test` 全绿(先跑一次确认基线,不得减少)
- [ ] `pnpm --filter @laizhixingxingdeli/web build` 通过

## 不涉及

- **不改**后端(见 R1 的例外说明)
- **不改**搜索 / 分页 / 状态 tab 的既有行为
- **不改**建群入口
- **不做**群列表的整页重设计——本票只改「行」与去掉那张卡片
- 不引入新依赖
