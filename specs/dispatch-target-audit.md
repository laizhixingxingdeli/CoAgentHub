# Spec: 自派警告与下发目标审计

> **状态**: Ready for Implementation
> **版本**: 1.0
> **日期**: 2026-08-23
> **来源**: `.scratch/diagnosis/self-dispatch.md`(codex 诊断,2026-08-23)
> **决策**: 只警告 + 落审计,**不拒绝**(用户 2026-08-23 决定)

## 背景

协调者两次把实现票派给了**它自己**,而空闲健康的执行器没被使用
(task `01a02cc0-b842-76ee-918a-2a683b90b9ae`,以及 2026-08-22 约 17:41 一次)。

诊断结论(已核实):**具体调用原因不能定论**——决策过程的 `outputTail` 是纯内存缓冲,
后端重启即丢。但可定论是三层缺口叠加:

| 层 | 缺什么 | 本票是否处理 |
|---|---|---|
| coordinator skill | 初次下发没规定排除自身 | 已修(`b5afbe2`) |
| MCP 工具 | `executorParticipantId` 零校验 | 不在本仓,另议 |
| **平台** | 同时握着 `senderId` 与 `audienceRef`,**却无任何信号** | **本票** |

## 决策:警告,不拒绝

诊断里提出的产品问题——直接拒绝会封掉「单 participant 部署」与「协调者故意本地执行」
两种合法场景。按 v3.9 §3.18,协调者/执行者本就该能用任何 CLI,单 participant 起步
是合理路径。

**这次事故真正的伤害不是「自派」本身,是自派之后无人察觉。**
所以本票做的是让它可见、可追溯,而不是堵死。

---

## 要求

### R1. 自派产生可见警告

`routes/group/messages.ts` 创建执行器任务时,若 **`senderId === audienceRef`**:

- 产生可见警告。形态自行设计并**在汇报里说明**,但必须满足:
  - **检视者不轮询也能看到**(它订阅的是收件箱,不是群消息流)
  - **不打断下发**——任务照常创建
- ⚠️ **不要拒绝、不要改为其他目标**。用户已明确决定只警告

### R2. 记录下发目标的选择上下文

诊断第 3 条:「task 持久化或 audit event 应记录目标选择原因、候选、选择者,
不能只依赖内存 `outputTail`。有了该记录才能对下一次事件定因。」

平台**知道**的事实(全部记录):

- 下发者 participant
- 目标 participant
- 是否自派
- **下发时刻本群有哪些候选执行器、各自状态**(空闲 / running / 最近失败)

平台**不知道**的:选择理由——那在调用方的推理里。

- 若调用方**主动提供**了选择理由,一并记录;**没提供不要编,留空**
- 存储位置自行判断(`task` 的字段 / 独立审计表 / 结构化日志),
  但**必须能在事后按任务查回来**——这是本票存在的唯一理由。
  纯 stdout 日志不满足要求(上次就是这么丢证据的)

### R3. 不要顺手加拒绝开关

- 不新增「是否允许自派」的配置项。多一个开关就多一处要维护、要测试、要文档化的分叉,
  而当前没有任何场景需要它
- 若实现中发现非加不可,**停下来写进汇报**,由检视者决定

## 验收标准

- [ ] `senderId === audienceRef` 的执行器任务会产生警告
- [ ] 警告对检视者可见且**无需轮询群消息**
- [ ] 自派任务**仍照常创建**,未被拒绝、未被改派
- [ ] 记录含:下发者、目标、是否自派、下发时刻的候选执行器及其状态
- [ ] 调用方未提供选择理由时该字段为空,**未编造**
- [ ] 记录可事后按任务查回,非仅 stdout
- [ ] **未新增自派开关**
- [ ] 新增测试覆盖:自派产生警告且任务创建成功、非自派不产生警告、候选上下文被记录
- [ ] `pnpm --filter server test` 全绿(见「执行环境提示」关于基线的说明)

## 不涉及

- **不改**前端(展示是后续独立票)
- **不改** coordinator skill(`b5afbe2` 已补目标选择规则)
- **不改** MCP 插件(不同仓;且按 v3.9 §3.18 该路径终将退役)
- **不做**拒绝自派
- 不引入新依赖

## 执行环境提示

- 本仓是 **pnpm** 项目
- 后端以 `pnpm --filter server start`(无 watch)运行中:改完需手动 build + restart
- ⚠️ **测试基线注意**:`test/dispatcher-fields.test.ts` 的 `afterAll` 钩子当前会超时,
  导致 `pnpm --filter server test` **退出码为 1**(用例本身 423 passed / 该文件 8 passed)。
  这是既有问题、**非本票引入**,另有票在修。判断基线时看**用例数**,不要看退出码
