# Spec: 前端展开实时输出明细

> **状态**: Frozen — 待实现
> **版本**: 1.0
> **日期**: 2026-08-27

## 背景

`two-tier-output-summary-and-detail`(已 Landed `a6ed2759`)让后端产出两层输出:
摘要行带 `#id`,完整原文落盘 JSONL,并提供展开 API:

```
GET /groups/:gid/tasks/:tid/output/:entryId    单条明细
GET /groups/:gid/tasks/:tid/output?detail=1    整份明细
```

前端目前只渲染扁平的 `outputTail`
(`RequirementTimeline.tsx` / `requirement-workspace.tsx` / `use-group-ws.ts`),
**没有任何展开入口** —— 用户看得到「在做什么」,但点不开「具体做了什么」。

## 要做的

### R1 — 带 `#id` 的摘要行可点击展开

摘要行形如 `[思考 #t7] 先确认守卫在哪个文件`。前端需识别其中的 `#id`,
渲染为可展开控件;展开时调单条明细 API 并就地显示完整原文。

⚠️ **不带 `#id` 的行保持现状**,不得变成可点击的空壳。

### R2 — 展开状态不干扰实时滚动

任务运行中摘要流持续追加。⚠️ 已展开的条目**不得因新行到达而自动收起**,
也不得阻止新行渲染。

### R3 — 失败要可见

单条明细取不到时(404 / 已清理 / 网络失败),⚠️ 就地显示失败原因,
**不得静默收起或显示空白**。

### R4 — 终态任务同样可展开

任务进入终态后明细仍在磁盘。⚠️ 终态任务的摘要行**必须同样可展开** ——
事后排障正是主要场景。

### R5 — ⚠️ 不得回归既有渲染

现有 `outputTail` 渲染、时间线布局、WS 增量更新一律不得破坏。
既有前端测试不得删改。

## 验收要点

- 运行中任务:点击带 `#id` 的摘要行能展开完整原文(贴截图或测试断言)
- 终态任务:同样能展开(必测,R4)
- 不带 `#id` 的行不可点击(R1)
- 展开后有新摘要行到达,已展开条目保持展开(必测,R2)
- 明细取不到时显示失败原因而非空白(必测,R3)
- 既有前端测试全通过且未改动(R5)
- 测试全绿,贴出用例数
