# Spec: 群设置面的四处内容问题

> **状态**: Landed — L3 通过(2026-08-24),实现 `a73a7f79 + ac960fc4(fix)`
> **版本**: 1.0
> **日期**: 2026-08-23
> **前置**: `specs/group-settings-drawer.md` v1.1 —— **本票排在其后**。
>   抽屉形态未落地就改内容,改完还要再跟着容器动一次。

## 背景

群设置面(`pages/app/groups/members.tsx`)有四处内容问题,都不影响功能,
但每一处都在给用户错误的暗示。

---

## R1. 副标题只描述了这个面的一部分

`lib/i18n/zh.ts:315`:

```
"members.subtitle": "成员在群组内分配角色(同一 participant 可在不同群组持有不同角色)"
```

而这个面实际有**三块**:基本信息与归档、**项目绑定**、成员与分工。副标题只说成员。

**要求**:改成能概括全部三块的一句话,或**直接删掉**。

宁可没有副标题,也不要一句只描述三分之一内容的副标题——它会让用户以为找错地方了。
执行者可自行判断哪种更好,在汇报里说明理由。

---

## R2. 项目绑定有两个重叠的输入位

`members.tsx:575-608`。已绑定时,界面上**同时**存在:

- 一个只读 `<code>` 显示当前路径 + 「解绑」按钮
- 一个**空的**输入框 + 「保存」按钮

于是绑定状态下,用户看到一个已有值和一个空输入框,**不知道该填哪个、填了会怎样**
(实际是覆盖)。

**要求**:合并成一个输入位。建议形态(执行者可提更好的):

- **未绑定**:输入框 + 「绑定」
- **已绑定**:显示当前路径 + 「修改」/「解绑」;点「修改」才把当前值**预填**进
  可编辑输入框

关键是**任何时刻只有一个地方可以输入路径**,且已绑定时的编辑起点是当前值,不是空。

---

## R3. 角色 chip 默认选中「观察者」

`members.tsx:78` 与 `:316`:

```ts
const [selectedRoles, setSelectedRoles] = useState<GroupRole[]>(["observer"]);
```

添加成员时默认勾上「观察者」。**默认值是一种推荐**,而观察者是这套协作里最不常用的
角色——真实场景里加进来的几乎都是 executor,偶尔是 coordinator / reviewer。

更麻烦的是:用户不改就提交,得到一个什么都做不了的观察者成员,**而界面没有任何提示**。

**要求**:去掉默认选中,**不预选任何角色**,并在未选任何角色时禁用「添加成员」
按钮 + 给出提示(「请至少选择一个角色」)。

⚠️ **不要改成默认选 executor** —— 那只是把猜错的对象换了一个。让用户显式选。

---

## R4. 分工 placeholder 长得像真实内容

`lib/i18n/zh.ts:326`:

```
"members.promptPlaceholder": "在本组你负责 code review,重点关注测试覆盖与可读性"
```

这是一句**完整、具体、可信**的分工描述。placeholder 在浏览器里是灰字,但灰字在这个
界面上到处都是(muted-foreground 是主力配色),用户很容易读成「这个成员已经有分工了」。

而分工提示词是**协调者真会读的字段**(skill §2.2 按 prompt 挑执行器),
误以为已填会直接影响下发行为。

**要求**:改成一望即知是示例的形态。例如加「例:」前缀,或改成描述性提示
(「说明该成员在本组的具体职责…」)。**不要**留一句可以直接当真值读的完整句子。
