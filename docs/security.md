# 安全模型与已知限制

CoAgentHub 把模型放到你的机器上、你的仓库里、用你的权限干活。请先读完这一页再用在重要的代码上。

## 一句话

**这是一个本机开发工具，不是多用户服务，也不是沙箱。** 假设你信任：运行平台的这台机器的其他本地用户、你配进去的模型提供商、以及目标仓库里的内容。

## 网络面：只监听回环，没有鉴权

- 平台只绑定 `127.0.0.1`，不对局域网和外网开放。
- HTTP 接口**没有内置认证**。能连上 `127.0.0.1:3101` 的任何本地进程，都能创建和控制 Mission、答复升级、终审合入集成分支、改候选池，也能让平台托管运行一个指定的适配器入口——也就是**以你的身份执行任意代码**。这和“本机有人能开一个 shell”是同一个信任级别。
- 所以：**不要**用端口转发、反向代理、`0.0.0.0` 绑定把它暴露出去；多用户的共享机器上不要运行；容器里运行时只在容器内部发布端口。
- 控制面留了注入点（`resolveControlPrincipal`，读需 viewer / operator，写需 operator），但仓库没有内置解析器，也没有启用。鉴权方案目前是明确推迟的事项。

## 子进程环境：默认只传基线，不传你的密钥

平台拉起 L2 / L1 的适配层子进程时，**不会**把整份 `process.env` 交给它，否则 agent 一句 `env` 就能读到你机器上所有密钥。

- 缺省只传 OS 与代理基线：`PATH`、`HOME` / `USERPROFILE`、`APPDATA`、`TEMP`、`HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 等 22 项（完整名单见 `src/runtime/spawn.ts` 的 `SPAWN_ENV_BASE_ALLOWLIST`）。
- 额外的变量必须由**部署方**用 `COAGENT_AGENT_ENV_PASSTHROUGH=A,B` 逐个点名；没有通配符。
- **未声明就拒绝启动**，而不是回落到“全传”。`scripts/coagent.mjs start` 缺省替你声明为 `-`（一个都不额外透传）。
- 因为 `HOME` 在基线里，pi 能读到你用 `/login` 存进 `~/.pi/agent/auth.json` 的凭据——**这意味着 agent 进程能读到这个文件**（见下）。

## 执行者不在沙箱里

- 执行者在 Mission 自己的 git worktree（`<项目根>/.coagent-worktrees/<id>/`）里工作，**用你的操作系统权限**跑 `bash`、写文件。工作目录是约定，**不是隔离**：一个执意越界的模型能读写你用户目录下的任何文件，包括 `~/.pi/agent/auth.json`。
- 平台在工具层做了一些**约束**（比如只读问答靠工具白名单、执行者没有改契约的口、执行者的 `git commit` 被拦下由平台按工作项做检查点、验证命令不经 shell 直接 argv 执行），这些是为了让模型少犯错，不是为了对抗恶意。
- 文件系统隔离、网络白名单、CPU / 内存 / 进程限额**都没有做**。要在不完全可信的仓库或模型上跑，请放进虚拟机或容器，用一个没有别的密钥的账号。
- 想降低 `auth.json` 暴露面：给适配层单独一个 pi 配置目录（`PI_CODING_AGENT_DIR`，并用 `--passthrough PI_CODING_AGENT_DIR` 交给子进程），里面只放这个用途的、额度受限的 key。

## 凭据与脱敏

- 仓库里没有任何凭据；`auth.json`、`models.json` 在你的 home 目录，不要提交。
- agent 产出的、要落盘或展示的文本（证据、失败原文、实时输出、验证输出）进门先过一遍**脱敏**：环境里名字像凭据的变量的值、私钥块、`Bearer …`、JWT、常见前缀的 key（`sk-`、`xai-`、`ghp_`、`AKIA`、`AIza`……）都会被替换成 `[REDACTED…]`。这是**尽力而为**的兜底，不是保证；不要依赖它来放心地让 agent 读密钥。
- 每一跳的运行令牌（`x-coagent-run`）只对那一跳有效，身份来自令牌而不是请求体；一跳结束令牌即吊销。

## 状态文件

状态文件（缺省 `.coagent-state.json` 及旁边的 `artifacts/`、`.lock-*/`）含有完整的 Mission、证据和输出，**没有加密**。已经在 `.gitignore` 里；备份它时当作敏感文件对待。同一时间只允许一个进程写它，不要手工编辑，平台开着时也不要读它。

## 遥测与外联

平台本体缺省不向外发任何请求，也没有遥测。（有一个可选的 Decision / Jev 信号功能，由 `COAGENT_DECISION_MODE` 控制，缺省 `off`；只有你显式打开 `shadow`，它才会请求你配置的端点，且只做审计、不具备执行权威。）会发网络请求的是：你配置的模型提供商；pi（版本检查、模型目录刷新、安装 / 更新遥测，可用 `PI_OFFLINE=1`、`PI_SKIP_VERSION_CHECK=1`、`PI_TELEMETRY=0` 关闭，并用 `--passthrough` 把这些变量交给适配层）；`setup` 时的 `npm ci`。

## 已知限制

- 预览版，Windows 上开发和验证；Linux / macOS 未真机验证。
- 没有鉴权、没有沙箱（见上）。
- 费用统计是 pi 按自带价目表折算的标价，不是账单；没有价目的 provider 记成接近 0。
- 文件版存储同一时间只有一个写者；多进程并发写用 Postgres 存储（`COAGENT_STORE=pg`）。
