# 前端实施准备：已确认设计
日期：2026-10-04。用户指示：「那你的意见进行优化。然后开始准备实施」。本轮准备设计、接缝和验收，不启动真实服务，不改变平台运行状态。采用最终三入口：首页、项目任务列表、角色与模型；任务详情从任务列表/首页进入。本文取代早期多方案建议，原型保留在 codex/frontend-design，生产重写，不合入原型代码。

## 实施范围与决定
1. 首页：紧凑平台状态（服务健康、运行数量、候选异常、桥接状态）和当前运行任务；未知/过期不显示正常。平台诊断按已有权威接口，不能凭握手宣称投递成功。无检视待办、文档页面或网页审批。
2. 项目任务列表：项目选择、统一任务表与状态，最新创建记录顶部，没有最近完成区块；保留队列位置与依赖，展示排序不更改执行顺序。所有状态都有详情入口。创建时间取真实 mission.created 活动或已提供权威字段，不能用 updatedAt 冒充；若列表缺少创建时间，显示未知并使用稳定顺序，必要接缝单独评估，避免对全部任务拉完整活动。
3. 任务详情：单一时间线、当前实时输出、选中环节用量/上下游沟通/历史输出/证据。长时间线折叠已完成节点，选择历史不自动抢回当前；按真实 attempt 分组，返工保留，未来阶段与已发生记录分开，并行工作按真实重叠关系展示。token 依已报告粒度，不均摊；历史正文缺失明确显示，不能用最新工单冒充历史版本。
4. 模型：四角色有序候选，上下移动、启停/移除沿用已批准 UI1 范围；保存整角色列表+全局 revision。冲突保留草稿并比较，下一调度生效，运行中的候选不变。空池失败关闭，明确操作后果。真实写操作遵守现有控制权限，不新增网页自签 reviewer/confirmedBy。
5. 导航：hash 路由保存项目/任务/环节，刷新与前进后退可恢复。原生 ESM、现有主题 token，无新依赖。中文标签、适量角色色；原始日志/错误码保留原文。竖向时间记录最新在上；候选优先级和输出正文按各自真实顺序。
