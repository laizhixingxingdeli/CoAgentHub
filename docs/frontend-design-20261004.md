# 第二轮设计：Mission 执行过程优先（2026-10-04）
本节取代下文「首页以项目统计为主」的建议。用户明确关注：项目中具体 Mission 到哪一步、实时输出、每个环节 token，以及环节之间的沟通信息。项目汇总降为次级视图，默认进入 Mission 执行过程；不再让费用卡片占据首屏主体。

## 主视图
桌面三栏：左侧项目/Mission 选择，中间步骤与尝试列表，右侧常驻当前实时输出＋选中环节详情。顶部明确当前运行到哪一步、WorkItem、尝试序号和等待原因。当前运行高亮，可一键定位；选择历史步骤时，不切走当前实时输出，历史输出在独立标签中查看。小屏先展示 Mission 选择、当前实时输出与详情，再展示步骤列表。
每个环节卡显示真实角色、状态、attemptId/WorkItem、时长与 token/费用；调查、派发、实现、验收、返工、独立检视（实际模式需要时）、L3 和平台合入按真实事件呈现。原型示例六步只是样例，正式产品不能假定固定六步，也不能把同一协调者 attempt 的多个操作拆成独立计费环节。
选中环节有三标签：交接沟通、本环节输出、证据与来源。沟通显示「谁传给谁、收到什么、交出什么」，保留工单、交回结果、验收意见/返工要求、升级问题与答复；详情带源事件、版本与时间，全文可展开，不用摘要替代原始正文。

## 已核实的数据接缝与限制
- src/web/task.js 已有按 attemptId 分组、环节用量、规划/工单/执行结果/L2 结论呈现，可重组现有组件，优先改布局与来源标注。
- GET activity 的 attempt.ended.data.usage 可提供结束环节用量；GET attempts/:attemptId 提供 usage/profile/output/evidence/toolActivity；live 以 cursor/chunks 增量返回，当前页面已处理 usage chunk。运行中只有适配器已上报的数据才显示暂计值，未上报显示未知；结束后用权威最终用量替换，不能和暂计重复相加。
- 用量分开展示 input/output/cacheRead/cacheWrite/total/cost，严格遵循现有 Usage 类型与适配器语义，不能因为字段缺失就当 0。每个 attempt 汇总与角色汇总是不同层级，不重复累计；缺少操作级用量时禁止均摊。
- 活动事件与工单/结果/lastReview 可呈现结构化交接。它们不等于全部聊天或内部推理。当前投影可能读取最新 plan/order/lastReview，旧版本正文若未持久化或暴露，必须标「历史版本不可恢复」，不能把最新正文冒充当时所传内容。完整逐环节不可变沟通快照若证据不足，应单列后端增量规格，用户确认后实施。
- 原型选择历史 L2 打回环节可看到返工要求，选择当前步骤可看到收到要求与尚未交回状态。静态输出与 token 均为样例，不连接实际服务。

# CoAgentHub 前端设计：项目总览优先
日期：2026-10-04。状态：设计待选择，未接入真实平台。分支 `codex/frontend-design`；原型 `src/web/frontend-design-prototype.html`，双击打开即可运行，URL `?variant=A/B/C` 切换方案，也支持底部按钮和方向键。全部数据为样例，状态仅在内存中，不调用接口、不消费 Delivery。

## 设计目标与首页选择
用户选择「项目总览：优先查看进度、费用与运行状态」。首屏回答：哪些项目正在推进、哪些任务被阻塞、已经完成多少、已报告花费多少。检视待办保留计数与阻塞提示，进入详情后才处理审批。建议以 A 为基础，C 的运行脉络放入项目详情；不把所有日志堆在首页。

|方案|主结构|适用场景|代价|
|---|---|---|---|
|A 项目矩阵（建议）|项目表格＋费用及当前运行侧栏|跨项目比较进度、状态与费用|需要进入详情了解事件过程|
|B 执行泳道|运行、待检视、排队三列|找阻塞与资源等待|同一项目可能分散在多列，比较项目较弱|
|C 运行时间线|主项目运行事件＋费用侧栏|追踪最近发生什么|项目数量增多时总览效率较低|

## 信息架构
六个入口：项目总览、项目与队列、检视待办、角色与模型、文档审查、平台状态。任务详情由项目/待办进入；项目配置、master 简报和历史记录留在项目上下文，不继续扩展导航。现有浏览器原生 ESM 与 node:http 保持，复用 tokens.css、ui.css 与 narrate.js，不新增 React/Vite 或构建流程。
- 项目总览：四项摘要（运行数、待处理数、队列完成数、累计已报告费用）、阻塞提示、项目矩阵、当前运行与最近完成。进度是已完成任务数/队列总数，不能称为验收覆盖率；已验收与已合入分别呈现。缺失费用显示未知，不按零计。日费用曲线暂不呈现。
- 项目与队列：配置版本、集成分支、顺序、依赖、可执行性及阻塞原因。既有队列不能拖拽重排；新冻结批次先预览顺序与依赖，再带版本提交。执行配置仅对未来启动生效，现有运行保持已固定配置。
- 任务详情：标题＋一行状态/费用/尝试摘要，完整 Contract 默认折叠但不截短。实时输出持续可见，尝试历史按 attempt 分组，L2/L3、验证报告、变更摘要分别展示。未提交报告不能显示通过。
- 检视待办：阻塞事项与非阻塞通知分组；显示任务上下文、判断依据和缺失证据。真实写入口要求有效身份和职责租约，观察模式可读。已读只处理通知；等待用户与业务批准分开；检查点已答复与已批准分开。Delivery ACK 始终由桥接器负责。
- 角色与模型：分类器、协调者、执行者、独立检视者四角色，候选有序、可停用、可移除、健康可查。独立检视者模型不是 L3 检视会话。编辑保留草稿，整角色列表带 revision 保存；409 保留草稿并比较，不自动覆盖。空角色池明确提示下一次调度失败关闭。
- 文档审查：差异、完整正文、revision/baseHash、批准/修改/撤回，批准后空档提交；代码合入不等待文档。平台状态聚合健康、候选故障与诊断；不展示凭据。master 简报只读，不提供合入按钮。

## 能力与接线边界
以下基于当前仓库接口与代码核实，原型未调用它们。
|页面/动作|当前接口|设计约束|
|---|---|---|
|项目与任务列表|GET /api/projects、/api/missions|状态来自权威响应，未知枚举保留原值并提示|
|任务证据|GET /api/missions/:id、/activity、/live、/attempts/:attemptId、/validation-reports/:id、/diff|diff 只有 stat；不能声称有 patch 或精确新增/删除行数|
|费用|GET /api/usage|先显示已有聚合；每日维度缺失，QueryRun 与 Mission 不盲目相加|
|待办|GET /api/reviewer/todos；POST 待办 action|acknowledge 不解决业务门禁；wait_user 会 park 并释放工作区，恢复按签名同步路径|
|检视职责|项目 reviewer-duty GET/POST，wait 长轮询|租约不是登录鉴权，不伪造 reviewer/generation|
|交卷决定|现有 reviewer finalize 接口|完整证据后 merge/send_back；不混用历史 PlanRun 与实际 Mission 路径|
|模型池|GET /api/pools、/api/pools/config；POST role/configure|全局配置 CAS；运行尝试候选不变，下一调度读取新配置|
|模型目录|runtime/models|仅 provider/model/label，不含 profile 映射或思考档位能力|
|项目队列/配置|项目 queue、execution-config GET/POST|expectedRevision、真实 confirmedBy；既有任务 Contract 不覆盖；当前无既有队列重排接口|
|文档|项目 documents 与 documents/:id/decide|revision/baseHash 核对与完整正文保留|

需要另行确认的后端增量：逐文件 patch/numstat、日费用聚合口径、模型目录到执行 profile 与思考档位的能力映射。现阶段使用已有 profile ID 与明确候选事实的高级编辑，不能从模型名字推断能力。鉴权 D1d、预算 B7、HTTP 传输 R1 继续暂缓，设计不变相实现它们。

## 交互与响应式验收
复用现有状态与主题 token；正文约 14px，表格约 13px，不用大量留白。桌面 1280×800 首屏展示摘要、项目列表和当前运行；800×600 将侧栏压成横向导航，摘要两列，任务实时输出优先，表格允许横向滚动。小屏不省略完整证据与 Contract。
每个面板分别处理加载、空数据、失败与过期状态，历史数据带更新时间；刷新失败不把旧数据伪装成当前。可见项目页约 5 秒刷新，任务证据约 3 秒、实时输出约 1 秒，切页取消旧请求，隐藏页暂停轮询，终态停止实时订阅。编辑草稿不随轮询覆盖，离开未保存编辑需提醒。键盘可达，按钮有焦点，未知状态不用颜色单独解释。
原型包含三首页方案、项目队列、任务实时输出、待办、四角色切换、草稿停用、409 冲突演示、文档和平台入口；提交均为演示。顶部始终标明无真实数据。原型不作为生产验收证据。

## 第三轮补充：运行时间线作为主导航
用户强调清晰看见运行时间线。主视图顶部增加时间线，节点显示开始/结束时刻、时长、角色、状态、token 和交接类型；当前执行节点高亮，选中历史节点有独立标记，节点点击联动下方详情。返工以新尝试保留，事件明细展示谁交给谁、打回理由与下一尝试启动时间。时间间隔只有时间证据时不推断等待原因。当前输出继续常驻。
原型采用按先后顺序的事件卡，不是按比例的甘特图，明确标注卡片宽度不代表耗时。尚未开始的步骤是预期路径，不冒充实际事件。正式页面遇到并行 WorkItem 必须按角色/WorkItem 分泳道，以真实起止区间表示重叠；不能串成假顺序。同一 attempt 内的调查、派发、验收等子事件可展开时间线，token 仍只按有归因的粒度展示，不均摊到每个子事件。实时自动跟随只在用户处于当前节点时进行；查看历史时不抢焦点，保留「定位当前」按钮。时间线默认任务全过程，密集记录可缩放或限定最近范围，原始时间与来源始终可查。
此次增加时间线仍为离线样例，脚本语法检查通过，浏览器视觉与交互验收尚未完成。

## 第四轮补充：字体与背景层级
按用户要求增加字体和背景颜色变化：页面浅蓝/淡紫/浅绿背景，深色渐变导航；协调者紫色、执行者青色、平台灰色，返工橙色、当前执行绿色。时间/attempt/数字使用等宽字体，标题加重，沟通正文保持易读中文字体；token 输入蓝、输出紫、缓存绿、总量琥珀。收到的内容用蓝底，交出的内容用紫底，实时输出采用深色终端，返工事件与启动事件分别橙底/绿底。颜色均配合角色/状态文字，不能成为唯一识别依据。此次色板只用于离线设计，正式实现须映射已有主题 token 并验证明暗主题和对比度。
