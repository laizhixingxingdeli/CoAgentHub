# ADR-0010: 协调者升为技术负责人（第一版）

**状态**: 已接受(2026-09-08)
**来源**: `specs/coordinator-as-technical-lead.md`（`docs/implementation-optimization-review-2026-09-07.md` §10）

## 背景

三角色拆分后，检视者职责 A 含 grill → 读架构 → 写 spec → 冻结。续跑任务书
（`buildResumeBrief`）只带回对 **L2** 足够的可复得事实（specRef/specHash、子任务状态、
diffSummary），**不**带回拆分计划、未派发工作项、Bug 诊断中已排除的假设——而这三样
恰是「上一轮想过什么」。协调者若只做「按冻结 spec 派发 + L2」，技术细化与根因调查
没有统一产物，续跑无法恢复。

## 决策

1. **切分线在职责 A 的中间两步**：三方编制下，检视者保留 §3 grill 与 §6 冻结；
   协调者接 §4 读架构与 §5 起草（含工作项拆分）。L3 **永远**是检视者的。
2. **指向，不复制**：协调者 skill 只写带范围的指向到 reviewer skill §4–§5；
   不把 Grill / To-Spec 正文抄回 coordinator skill（与既有 §1.2 指向机制同一纪律）。
3. **两方编制约定不变**：无 reviewer 时协调者仍**整体**继承职责 A（§1.2 逐字保留）。
4. **计划另存 `plans/<spec 同名>.md`**：spec 是冻结锚点（specHash），计划会回填 taskId、
   标完成——二者生命周期不同。路径由 `specRef` 推得，故续跑**不必**改 `buildResumeBrief`
   或任何平台代码。平台不解析计划文件。
5. **工作项 ≠ task**：未派发工作项不得伪装成 queued task；重派多 task 可属同一工作项。
6. **诊断段必含「被排除的假设」**；根因未定先派带停止条件的调查任务。
7. **续跑顺序**：读计划 → 读子任务状态 → 以 task 事实校正计划。派发成功但未回填
   taskId 时不得只看计划就重派。父子关系须验证，不得假设。
8. **第一版不引入** DB 工作项实体、计划 API/前端、自动依赖调度（第二/三版另案）。

## 后果

- 流程变为：检视者明确需求 → 协调者技术细化与拆分 → 检视者确认冻结 → 协调者下发。
  进行中的需求按旧流程走完，不中途切换。
- 无 schema / 平台行为变更，不需要构建或重启。
- 与 ADR-0005（角色解绑）相容：职务仍由群角色表达；本 ADR 只收紧 skill 级职责边界。
- 与 ADR-0009 无关（未新增分流判据）；若后续把「是否有计划文件」写成平台判据，须另开 ADR 并指名事实。
