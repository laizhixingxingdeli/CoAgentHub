# ADR-0011:验收测试必须先证明它在缺陷状态下是红的

**状态**:已接受(2026-09-12)
**相关**:[ADR-0009](0009-judgments-must-name-the-fact.md)(判据必须指名它所裁定的事实)

## 背景

2026-09-12 一轮连续交付里,有五张票的验收都遇到同一个形状的问题:
**测试写了、跑绿了,但它在缺陷存在时也是绿的** —— 于是它什么都没验。

具体形态各不相同,错法一致:

| 票 | 若不加约束,测试会怎么假绿 |
|---|---|
| spawn 前停止守卫 | 只断言「任务终态是 cancelled」—— 缺陷状态下结果路径**本来也会**补记 cancelled,区别只在执行器到底 spawn 没 spawn |
| skill 指纹一致性 | 断言「任务书的指纹 == 端点的 version」,而两边**调的是同一个函数** —— 任何实现下都恒等,是同义反复 |
| CLI 静默超时 | 只断言「失败原因是『执行器静默超时』」—— 不区分 `retryable` 真假,而那两条分支文案相近、重试语义相反 |
| pump 信号注册 | 不断言「模块加载后已注册」—— 注册丢失的表现是**任务静默不再派发**,没有任何报错 |
| 抽出成功分支的 `return` | 声称「漏了会误入 `else`」并据此加 `return` —— **论证本身是错的**,而当时没有任何测试能分辨加没加 |

第五条尤其说明问题:**代码是对的,理由是错的,而测试两种情况下都绿**。
错误的理由会留在提交信息里误导后来人,测试却给不出任何信号。

## 决策

**一条验收测试在被采信之前,必须先证明它能在缺陷状态下变红。**

落到三种可操作的手法(用哪种由改动性质决定):

1. **否定对照(改动前跑)** —— 把生产代码**单独**回退到改动前,跑新测试,
   **必须红**。适用于修缺陷的票。
   例:`git checkout HEAD~1 -- <file>` 后跑,3 条全红,还原后全绿。
2. **变异注入** —— 在生产代码里注入一个**最小的、针对性的**错误
   (把 `retryable: true` 改成 `false`、把指纹从 12 位截成 10 位、
   注释掉注册行),跑测试,**必须红**;之后**立刻还原**。
   适用于补覆盖、或验收点是某个具体取值/分支的票。
3. **可观察事实而非推断结论** —— 断言落在**只有在正确实现下才可能出现**的
   外部事实上。
   例:让假执行器 bin 一启动就写哨兵文件,断言**文件不存在**(证明没 spawn);
   监视 `runA2AExecutor` 的调用次数,断言**从未被调用**。

## 后果

- **票面要写明禁止什么。** 光说「加个测试」不够 —— 要指出这张票上
  **哪种断言是假绿的**(如「不接受『状态是 cancelled』作为唯一判据」),
  否则执行侧会选最省事的那条。
- **验收里多一行成本,换掉一整类无效测试。** 否定对照通常只是一次
  `git checkout` + 一次跑;变异注入是改一行 + 跑 + 还原。
- **检视者自己也要做一遍,不采信汇报。** 2026-09-12 的五次验证全部由检视者
  独立复跑;其中「成功分支的 `return`」一条,正是检视者做变异时发现
  **执行侧的论证是错的**(52 条测试在去掉 `return` 后依然全绿)。
- **不适用的情形要说清楚。** 纯搬运票(逐字移动代码)靠的是
  **逐字 diff 自证**,不是测试 —— 那类票的测试只做兜底,
  本 ADR 的要求落在 diff 上(见 `specs/queue-ts-decomposition-design.md` §4)。

## ⚠️ 变异要打在真正覆盖该分支的测试上,不是票面清单上

2026-09-12 抽 `runOne` 剩余终态分支时踩过一次:

给「A2A 记忆」分支(**不是早退**,处理完要继续往下走)的调用点**注入一个
多余的 `return`**,票面清单里那 8 个文件 **62 条全绿** —— 看起来像是
「这条路径没人管」。

但真相是:覆盖它的是 `executor-trigger.test.ts` 的三条 a2a 用例,
而**那个文件被我排除在票面清单之外**(因为它在本机有 8 条既有红,
是假执行器 bin 起不来的老问题)。把同一个变异打到那个文件上,
**3 条立刻变红**。

**教训有两层:**

1. **变异跑在票面清单上只能证明「清单够不够」,不能证明「有没有覆盖」。**
   要判定覆盖,得先找到真正执行该分支的测试(插桩计数是可靠办法),
   再对它下变异。
2. **不要因为「这个文件本机有既有红」就把它整个排除出验收清单。**
   正确做法是纳入,并在票面写明**确切的既有失败条数与成因**
   —— 排除掉它,就等于把它覆盖的分支也一并放弃了。

## 与 ADR-0009 的关系

ADR-0009 管的是**生产代码的判据**:它读的是近似量,却被当作另一个事实。
本 ADR 管的是**验收的判据**:它根本不会变红,于是任何事实都没被裁定。

两者是同一件事的两端 —— **一个判据要有意义,前提是它在该为假的时候真的为假。**
